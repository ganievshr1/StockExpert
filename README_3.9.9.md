# StockExpert 3.9.9: проверка H1, H2 и H3

В разделе «Для разработчика» появились две вкладки: «Ручная проверка метрик» и «Автоматическая проверка метрик». Внизу каждой вкладки находится раздельное сравнение H1, H2 и H3 по сохраненным сессиям, моделям и экспериментам. Кнопки Excel и JSON выгружают отчет только по выбранной гипотезе и конкретной версии оценки.

## Обновление в WSL

Архив содержит полный backend и frontend. Новых таблиц относительно 3.9.8 не требуется: используются существующие снимки запусков, версии оценок и лабораторные эксперименты.

Сохраните скачанный архив в `C:\Users\ganie\Downloads` и выполните в Ubuntu:

```bash
mkdir -p /home/ganie/StockExpert3.9.9
unzip -o /mnt/c/Users/ganie/Downloads/StockExpert_3.9.9_metrics.zip -d /home/ganie/StockExpert3.9.9
cd /home/ganie/StockExpert3.9.9
bash install_update.sh
```

Скрипт ищет прежний `.env`, в том числе в StockExpert3.9.8, использует прежнее имя Docker-проекта `stockexpert-backend`, создает резервную копию PostgreSQL и проверяет количество исторических записей до и после обновления. Во время активных заданий обновление останавливается. Docker-тома и модели сохраняются. Если `.env` не найден автоматически, скопируйте его из предыдущей установки в `stockexpert-backend/.env` и повторите запуск. Не используйте `docker compose down -v`.

Интерфейс: http://localhost:5173. Войдите администратором.

## Эталон и исходные данные

`reference/StockExpert_reference_99.xlsx` предназначен для загрузки через раздел разработчика. JSON рядом содержит ту же разметку; импорт обеих форм дает одинаковую контрольную сумму.

- 99 складских позиций, 58 разных описаний. Строка 1 с системой ЕхСО является изделием, хотя имя файла содержит 98.
- 169 значений характеристик с дословными цитатами. Неявные технические значения из кодов моделей не придуманы.
- 27 конечных категорий, назначенных всем 99 позициям.
- 8 учебных запросов, 792 решения по всем парам, 22 подходящие пары. Запросы находятся в `reference/H3_Q01.txt` … `H3_Q08.txt`.

Это проект разметки, подготовленный ChatGPT по исходным строкам, а не подтвержденное заключение независимого отраслевого эксперта. Авторство и ограничения записаны в самом файле. Назначение серий ЕхСО, СЭО, СУДРВ и ЗК следует утвердить с предметным экспертом. Цифры внутри обозначений без явных единиц остаются обозначениями.

Для H1 и H2 загрузите исходный Excel `База_исх_98(6).xlsx` или его побайтовую копию `reference/Baza_ish_99.xlsx`. Для складского листа подтвердите: строка заголовка 0, описание — столбец C, столбец B не передавать модели как категорию. Это исключает потерю первой позиции и утечку исходной классификации.

Для учебного H3 добавьте в одну сессию все восемь TXT как документы потребности, сохраняя каждый файл без редактирования. В каждом TXT одна позиция. Если использовать собственные опросные листы, подготовьте их отдельную разметку относительно всех строк каталога. Файл эталона проверяет SHA-256 источников и координаты, поэтому не подставляет чужие ответы.

## Автоматическая проверка

1. Откройте «Для разработчика → Автоматическая проверка метрик» и загрузите XLSX-эталон.
2. Выберите сессии с той же исходной базой и нажмите «Рассчитать метрики выбранных сессий». Используются сохраненные предсказания, LLM повторно не вызывается.
3. Для конкретного старого запуска выберите сессию в верхнем списке, затем «История запусков» в лабораторном блоке и «Пересчитать». Снимок должен существовать. Более ранние состояния, не сохраненные старой программой, не восстанавливаются из текущих паспортов.
4. В «Сравнение расчётов по гипотезе» выберите H1, H2 или H3. Скачайте отчет выбранной строки в Excel/JSON. Для сравнения используйте одинаковую группу разметки, исходных строк и протокола. Совпадение группы не гарантирует одинаковой нагрузки на сервер при измерении времени.

Каждый пересчет создает отдельную неизменяемую версию. В новых версиях сохраняются исходные строки, ожидаемые и полученные значения, расхождения и пары H3. Прежние версии оценок не удаляются. Старые версии, в которых детали не сохранялись, содержат только реально доступные данные; повторный пересчет по сохраненному снимку создаст полноценный новый отчет.

## Ручная проверка

Выберите вкладку ручной проверки и сессию. В «Проверка качества» выберите нужный завершенный расчет. Показаны исходные ячейки и сохраненный паспорт.

- H1: режим «Извлечение технических параметров». Отметьте проверенные поля, исправьте значения и единицы. Через «Добавить параметр, пропущенный моделью» можно внести отсутствующий ключ: он учитывается как FN. Для чисел используйте единицу, для текста — `none`. В комментарии сохраните цитату. Совпадение названия доступно как дополнительная метрика.
- H2: режим «Только категория». Выберите верную конечную категорию. Если ее нет в дереве, введите название в отдельное поле: отсутствующее или другое назначение модели считается ошибкой. Пустой ответ не означает правильную классификацию.
- H3: режим «Подходит / не подходит». Проверьте все складские позиции каждой потребности, включая позиции вне shortlist. Неполная разметка не дает Recall для этого запроса. Если старый движок не сохранял все пары, требуется новый подбор.

Нажмите «Завершить экспертную проверку» или «Пересчитать» в ручном лабораторном блоке. Ручные оценки не заменяются Excel-эталоном. При переключении запуска сверяйте ID в обоих селекторах: очередь ручной проверки и лабораторный блок выбирают расчет независимо.

## Методы из экспериментального протокола презентации

| Гипотеза | Поддержанные сравнения |
|---|---|
| H1 | Сохраненный результат; регулярки и словари; исходный ответ LLM; LLM с проверкой цитат и единиц; LLM с дополнением пропусков правилами |
| H2 | TF-IDF + k-means; HDBSCAN по исходным строкам; HDBSCAN по паспортам; LLM напрямую; HDBSCAN + LLM |
| H3 | BM25; Dense; Dense + BM25 + RRF; RRF + правила; полный каскад; каскад без правил; Dense + SPLADE; полный Cross-Encoder |

Qwen2.5-7B Q4/Q5, Qwen3-8B, Qwen2.5-14B и серверный профиль DeepSeek выбираются существующим переключателем. Наличие профиля не означает наличие весов или доступность API. Для SPLADE нужен локальный `SPLADE_MODEL_PATH`, для Cross-Encoder — включенный reranker и установленные зависимости. Недоступный метод возвращает явную ошибку, а не подменяется другим алгоритмом. Литературные обзоры NER, BERTopic, TaxoGen и TnT-LLM не объявляются реализованными воспроизведениями этих публикаций.

Параметры обучения, seed, k, min_cluster_size и повторов H3 задаются перед запуском. Один эксперимент использует одну выбранную LLM. Для сравнения LLM повторите одинаковый набор методов с другим профилем; все результаты остаются в истории. Каждый эксперимент создает отдельные результаты, рабочие паспорта не перезаписываются.

H1 и H3 основного процесса работают с таксономией и без нее. Выбор H2 делается до обработки. Лабораторные методы H2 можно проверить отдельно даже на снимке процесса, в котором H2 был отключен.

## Как трактовать гипотезы

H1 в слайде 7: micro-F1 извлеченных технических значений ≥ 0,94 и преимущество над регулярками. Precision = TP/(TP+FP), Recall = TP/(TP+FN), F1 = 2TP/(2TP+FP+FN). Неправильное значение дает FP и FN. Количество значений может быть больше 99; знаменатель здесь не число строк. Дословное совпадение названий не заменяет эту метрику. Для LLM и гибрида при наличии результата регулярных выражений вычисляется парная разница F1 и bootstrap-интервал по группам дубликатов.

В слайде 6 формулировка «LLM/регулярных выражений … превышающую регулярные выражения» смешивает исследуемый и базовый методы. Для отчета использовать: «LLM с проверкой цитат и нормализацией единиц обеспечит micro-F1 ≥ 0,94 и положительный прирост к регулярным выражениям на одной независимой тестовой выборке». Интервал прироста должен быть выше нуля.

H2: основной показатель — конечная категория, не обязательно третий уровень. Описательная оценка сохраненного запуска сопоставляет кластеры и экспертные категории на всей разметке и поэтому не доказывает обобщение. В лабораторном тесте группы и соответствие фиксируются на обучении. Дубликаты находятся в одной части. Шум и новые категории учитываются как ошибки. Для полного подтверждения нужен независимый тест и сравнение с базовым k-means.

H3: среднее Recall@150 по запросам после правил и до Cross-Encoder. Полный Cross-Encoder оценивается по его первым 150 результатам. Нужна разметка всех позиций для каждого запроса. Индексация и загрузка моделей отделены от времени запроса. Старые результаты без pre_rerank_rank явно помечаются как legacy. Для вывода о преимуществе нужен меньший p95 полного каскада относительно полного Cross-Encoder при одинаковом сервере, моделях и нагрузке.

## Фактически выполненные расчеты

Это предварительная проверка на наборе для разработки, размеченном ChatGPT. Правила в исходном проекте уже адаптировались к этой базе. Seed 42, доля обучения 0,7, k=8. Получилось 66 обучающих и 33 тестовые строки; дубликаты не разделялись между частями.

| Расчет | Результат | Ограничение |
|---|---|---|
| H1, регулярки, все 99 строк | TP 136, FP 23, FN 33; Precision 85,53%, Recall 80,47%, F1 82,93% | Описательная оценка всей базы |
| H1, регулярки, 33 строки тестовой части | TP 35, FP 2, FN 9; F1 86,42% | Разделение существующей разработочной базы, не независимый новый источник |
| H2, TF-IDF + k-means | Accuracy 39,39%, ARI 0,5614, V-мера 0,7633 | 33 строки, k=8; настройки не подбирались по тесту |
| H3, BM25 | Recall@150 100%, nDCG@10 0,8464 | Только 99 позиций и 8 учебных запросов |

Время BM25 записано в JSON-отчете, но относится к среде этой проверки, а не вашему компьютеру. LLM, Dense, HDBSCAN на реальных эмбеддингах, SPLADE и полный Cross-Encoder здесь не измерялись. Порог H1 у регулярных выражений не достигнут; H2 у этого базового k-means также ниже цели. Эти результаты не опровергают и не подтверждают качество еще не измеренных LLM-методов. H3 на таком объеме не подтверждает гипотезу про 12 000 позиций. Итог: все три исследовательские гипотезы пока остаются неподтвержденными.

Отдельные результаты находятся в `validation/H1_regex_99.json`, `H1_offline_experiment.json`, `H2_offline_experiment.json`, `H3_offline_experiment.json`. Для повторения CPU-расчетов:

```bash

```

Команда использует только поставленные файлы эталона и CPU-методы, не обращается к LLM и не изменяет производственную базу. Нужны зависимости backend. Для автотестов: `python -m pytest -q`. Для frontend: `npm ci`, `npm test`, `npm run build`.
