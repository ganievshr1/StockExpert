# StockExpert

Автор: **ganievshr**. Версия: **3.9.13-b1.2**.

StockExpert помогает специалисту по материально-техническому обеспечению подобрать позиции из каталога остатков под новую потребность. Программа извлекает характеристики из описаний, сопоставляет изделия, ранжирует кандидатов и показывает совпадения и расхождения. Это сокращает ручной поиск по Excel; окончательное решение о пригодности позиции принимает специалист.

## Что поступает на вход и что получается

| Вход | Назначение |
|---|---|
| Каталог ЕБДЗ/остатков в `.xlsx` | Наименования и характеристики доступных МТР; соответствие столбцов задаётся в интерфейсе |
| Потребность в `.txt` | Описание одной позиции либо список: в режиме «Список позиций» каждая непустая строка — отдельная потребность |
| Дополнительно: `.xlsx`, `.docx`, `.pdf` | Документ потребности в обычном режиме разбора; для построчного списка нужен TXT |

На выходе — список подходящих кандидатов, результаты сравнения характеристик и отчёты Excel/PDF. Подготовленную базу можно использовать для следующих запросов. Раздел разработчика содержит проверки извлечения, таксономии, поиска и обработки конкурентных запросов.

Интерфейс работает на React/Vite, API — FastAPI. Фоновые задания выполняет Celery через Redis; в Docker также запускаются PostgreSQL, Qdrant, MinIO и Ollama.

## Локальный запуск в Windows / WSL Ubuntu

Нужны WSL 2, Python 3, `curl` и запущенный Docker Desktop в режиме Linux containers. В Docker Desktop включите WSL 2 engine и интеграцию с Ubuntu: **Settings → Resources → WSL Integration**. Для приведённого CPU-варианта требуется Docker Compose **2.24.4 или новее**. При первой сборке нужен интернет для образов, зависимостей и весов моделей.

Команды выполняются в терминале Ubuntu. Если проект находится в другой папке, измените только команду `cd`:

```bash
cd /home/ganie/StockExpert_release/repository
docker version
docker compose version

export B1_PROJECT=stockexpert-backend
export STOCKEXPERT_NETWORK=stockexpert-network
export B1_CPU=1
export BACKEND_PORT=8002
export FRONTEND_PORT=5175
export MINIO_CONSOLE_PORT=9003

bash b1.sh init
```

`init` создаёт `stockexpert-backend/.env` и сохраняет уже существующий файл. Логин и случайный пароль для входа находятся в `ADMIN_USERNAME` и `ADMIN_PASSWORD` этого файла; откройте его локально в редакторе. Если обновляете существующую установку с прежними Docker volumes, используйте её прежний `.env`: новые случайные пароли не изменяют пароль уже созданной базы PostgreSQL.

По умолчанию выбрана локальная модель `qwen3:8b-q4_K_M`. Для Qwen2.5-7B Q5 до первого запуска измените три строки в `.env`:

```dotenv
LLM_DEFAULT_PROFILE=qwen25-7b-q5
LLM_PROVIDER=ollama
LLM_MODEL=qwen2.5:7b-instruct-q5_K_M
```

Затем запустите сервисы и загрузите модели:

```bash
bash b1.sh start shared
bash b1.sh models
bash b1.sh status
```

`models` загружает эмбеддинг `bge-m3` и выбранную LLM. Веса reranker загружаются при первом использовании; его запуск по умолчанию выполняется на CPU. Первая сборка и скачивание моделей могут занять продолжительное время.

Для ускорения Ollama на NVIDIA сначала проверьте `nvidia-smi` в WSL и доступность GPU в Docker Desktop. До запуска, либо после завершения активных заданий, выполните:

```bash
export B1_CPU=0
bash b1.sh start shared
```

Это включает NVIDIA-устройство у Ollama; режим CUDA reranker настраивается отдельно в [инструкции параллельного запуска](docs/B1_PARALLEL_GPU_RU.md).

Сохраняйте одинаковые значения `B1_PROJECT`, `STOCKEXPERT_NETWORK`, `B1_CPU` и портов для следующих команд. В новом терминале повторите блок `export`. Если порты заняты другой установкой, остановите её штатно либо задайте свободные `BACKEND_PORT`, `FRONTEND_PORT`, `MINIO_CONSOLE_PORT` до запуска.

## Адреса и порты

При настройках выше:

| Адрес на компьютере | Сервис | Порт внутри контейнера |
|---|---|---|
| [http://localhost:5175](http://localhost:5175) | Интерфейс через Nginx | `80` |
| [http://localhost:8002/docs](http://localhost:8002/docs) | API и Swagger | `8000` |
| [http://localhost:8002/health/live](http://localhost:8002/health/live) | Проверка процесса API | `8000` |
| [http://localhost:9003](http://localhost:9003) | Консоль MinIO | `9001` |

Эти порты опубликованы только на `127.0.0.1`. PostgreSQL (`5432`), Redis (`6379`), Ollama (`11434`), Qdrant REST (`6333`) и API MinIO (`9000`) используются внутри Docker-сети и отдельно на компьютер не проброшены. Фронтенд проксирует `/api/` в `backend:8000`.

## Проверка и первый подбор

```bash
curl -fsS http://localhost:8002/health/live
curl -fsSI http://localhost:5175/
bash b1.sh status
```

Успешный `/health/live` подтверждает доступность процесса API, но не выполнение заданий или готовность моделей. Проверьте полный сценарий:

1. Откройте интерфейс и войдите с данными из `.env`.
2. Создайте сессию, загрузите Excel-каталог и TXT-потребность. Для нескольких строк выберите режим списка позиций.
3. Подтвердите соответствие столбцов, выполните нормализацию; если включена таксономия — завершите её и утвердите категории.
4. Запустите подбор, дождитесь результата и проверьте кандидатов. Скачайте отчёт Excel или PDF.

Для первого прогона используйте небольшой фрагмент своего каталога и одну потребность. Полная ЕБДЗ, рабочая база данных и резервные копии в исходный архив не входят; схема и миграции включены.

## Логи и остановка

```bash
bash b1.sh logs
bash b1.sh stop
```

`stop` сохраняет данные в Docker volumes. Для обычной остановки не требуется `docker compose down -v`.
