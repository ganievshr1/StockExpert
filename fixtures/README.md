# Синтетические входы для B1

**Все 12 000 строк созданы программно. Это не реальный ЕБДЗ и не экспертная
разметка для оценки качества LLM, классификации или поиска.** Сочетания параметров
служат разнообразными текстовыми входами; они не подтверждают существование,
стандартность или техническую применимость изделий.

`B1_catalog_12000_SYNTHETIC.xlsx` содержит один лист `SYNTHETIC_12000` с заголовком
в строке 1 и ровно 12 000 записями. Столбец `synthetic_id` идентифицирует строку,
столбец `Наименование` содержит исходный текст, `Тип данных` явно помечает
синтетическое происхождение. Есть по 3 000 текстов труб, задвижек, шаровых кранов
и фланцев. Все исходные описания уникальны. Готовых JSON-паспортов в комплекте нет:
их должно получить само приложение выбранным методом нормализации.

При загрузке Excel подтвердите сопоставление: заголовок — строка 1,
наименование — **только столбец B «Наименование»**, категория — не задана.
Идентификатор и пометку синтетических данных не нужно включать в описание.
Технические индексы приложения: `header_row=1`, `name_columns=["1"]`.

Для подготовки исходной сессии B1 используйте каталог Excel и **все десять
отдельных файлов `requirements_10/Q01.txt` ... `Q10.txt`**, либо общий TXT в явно выбранном режиме «Список позиций — одна строка = одна позиция». Каждый файл содержит
одну потребность. Загрузите эти десять файлов потребностей **в одну исходную
сессию до запуска нормализации**. Затем подготовьте эту сессию и выберите её
в интерфейсе B1. В ней должны появиться 12 000 позиций каталога и не менее
десяти нормализованных позиций потребности. Десять отдельных подборов до запуска
B1 создавать не требуется: испытание использует потребности выбранной сессии.

`B1_requirements_10_SYNTHETIC.txt` содержит общий список из десяти строк.
В 3.9.13-b1.1 его можно загружать одним файлом, выбрав режим
**«Список позиций — одна строка = одна позиция»**. При обычном разборе
опросного листа программа по-прежнему может считать весь список одной потребностью. Тексты взяты из синтетических описаний; это не эталон
релевантности и не доказательство качества поиска.

`B1_catalog_12000_SYNTHETIC.csv` содержит те же значения для независимой проверки.
`B1_fixture_manifest.json` фиксирует seed, количества, источник, сопоставление
колонок, семантическую контрольную сумму и SHA-256 файлов.

Проверка готового комплекта стандартным Python из корня проекта:

```bash
python experiments/generate_b1_fixture.py --validate-only
```

Воспроизведение текстов и CSV без дополнительных библиотек:

```bash
python experiments/generate_b1_fixture.py --data-only --output-dir /tmp/b1_synthetic_rebuild
```

Полная регенерация в обычной WSL/Python-среде использует `openpyxl`, который
уже указан в зависимостях бэкенда. Запускайте команду в том же Python-окружении:

```bash
python experiments/generate_b1_fixture.py --xlsx-engine openpyxl
```

Режим по умолчанию `--xlsx-engine auto` выбирает `@oai/artifact-tool`, если
доступен Codex runtime, и `openpyxl` при его отсутствии. Оба варианта создают
одинаковые исходные значения, заголовки, замороженную строку 1 и фильтр.
XLSX создаётся локально выбранным экспортёром.

В этом комплекте XLSX не включён; перед загрузкой создайте его указанной командой. Содержимое CSV/TXT воспроизводимо с фиксированным seed. Бинарный
хэш нового XLSX может отличаться из-за служебных метаданных ZIP/экспортёра;
семантический хэш данных и проверка равенства значений позволяют сравнивать
содержимое независимо от этих метаданных.

`B1_thermocolumn_10.txt` — отдельный пример из предоставленного пользователем файла: десять наименований термоколонок, по одному на строку. Используйте режим построчного списка; это пример формата входа, а не разметка качества подбора.
