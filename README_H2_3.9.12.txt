Дата подготовки: 31.10.2026

1. ЧТО ИСПРАВЛЕНО

В лабораторном разделе H2 добавлены загрузка экспертного Excel/JSON, предварительная
проверка разметки и разделения, запуск пяти методов и отдельный подробный отчёт H2.
Основная метрика приведена к методике индивидуальной презентации, слайды 12–16:
Accuracy = N_correct / N_test по конечной категории общего фиксированного дерева.
Для трёх уровней это Accuracy L3. Отказы и неизвестные категории считаются ошибками.
Дополнительно показаны ARI, V-мера, силуэт, доля без категории, шум HDBSCAN,
ошибки родителей, Accuracy L1/L2/L3, интервалы Accuracy и парных разностей.
Венгерское сопоставление на тесте оставлено только как дополнительная диагностика.

Пять методов:
  1) TF-IDF + k-means по исходным строкам — базовый метод.
  2) Векторизация исходных строк + HDBSCAN.
  3) Векторизация нормализованных паспортов + HDBSCAN.
  4) LLM напрямую по тем же паспортам, с выбором категории фиксированного дерева.
  5) Нормализованные паспорта + HDBSCAN + LLM — полный метод H2.

У методов 1–3 соответствие групп категориям определяется только по train.
В методе 5 LLM получает примеры обучающих групп, предлагает названия L1–L3
и выбирает конечную категорию утверждённого дерева. Тестовые ответы ей не передаются.
Методы 4 и 5 знают перечень категорий, но не экспертные категории тестовых позиций.
Паспорта, модель векторизации, веса и разделение должны совпадать между методами.
Вес названия по умолчанию 1, вес технических атрибутов 2; при отсутствии атрибутов
используется название. Параметры фиксируются до просмотра результатов теста.

Ручная и автоматическая проверки, история расчётов и отдельные сравнения H1/H2/H3
сохранены. Новый протокол H2 отделён от старых расчётов: старые результаты нужно
перезапустить, чтобы получить новую оценку. Основной переключатель таксономии
сохраняется. Лабораторный эксперимент H2 доступен и при выключенной таксономии
основного расчёта; лабораторный H2 сам проверяет методы классификации.

4. ПОДГОТОВКА ЭТАЛОНА H2

Откройте StockExpert_H2_reference_100.xlsx.
На листе «Проверка H2» доступны описание каждой строки, предложенный путь категории,
пометка об уточнении, предварительная часть train/test и поля решения эксперта.
29 строк требуют повышенного внимания: тип предложен по сокращённому обозначению.
На листе «Таксономия» приведены правила предложенных классов.

Машинные метки редактируйте на листе «Паспорта», столбец category_path (I):
  ["Трубопроводы","Арматура","Краны"]
Это JSON-массив строк; у данной разметки три уровня. Названия и иерархию эксперт
утверждает до теста. Правка только полей «Решение эксперта» не изменяет категорию.
После изменения состава дерева актуализируйте справочный лист «Таксономия».

Столбец split_group (K) объединяет смысловые дубли. Заполнены две группы:
  строки 22 и 24 — плита ПДН АтV 55;
  строки 91 и 93 — одна модель крана КШ50*16, разная полнота записи.
Одинаковые тексты и позиции одной группы всегда попадают в одну часть выборки.
Проверьте полноту этих групп до эксперимента. Это группы дублей, а не категории:
не объединяйте все трубы или все краны в одну split_group.
Справочная колонка train/test в Excel рассчитана для исходных групп и seed=42;
после правок действительное разделение смотрите в предварительной проверке и отчёте.

Не меняйте ID, SHA-256, номера строк, исходные ячейки и базу. Идентификация выполняется
по SHA-256 + листу + строке; простое переименование исходного файла допустимо,
пересохранение Excel изменяет SHA-256. На листе «Настройки» обновите author/version
и зафиксируйте, какие решения эксперт утвердил. Сохраните проверенный эталон отдельно.

5. ПОШАГОВАЯ ПРОВЕРКА H2 В ПРОГРАММЕ

Шаг 1. Выберите сессию с этой базой или создайте новую. Настройка EBDZ_100.xlsx:
  лист Лист1; строка заголовка 0 (заголовка нет);
  столбец названия только B, то есть нулевой индекс "1";
  столбец категории не выбран, то есть null.
Не подавайте столбец A с учётной группой модели: он подсказывает категорию.
Если старые паспорта строились с A, для чистого эксперимента пересчитайте H1
без A. Такой старый расчёт можно анализировать отдельно как режим с контекстом.

Шаг 2. Завершите основной расчёт H1 по 100 позициям. Для H2 опросные листы
не нужны. Паспорта нужны методам 3–5; при отсутствии паспортов они сообщат ошибку.
Основную таксономию можно выключить, чтобы не строить её лишний раз.

Шаг 3. Откройте «Для разработчика» → автоматическую проверку/сравнение метрик.
Выберите нужную сессию и завершённый запуск. В блоке H2 загрузите Excel через
«Загрузить экспертную разметку H2 (Excel или JSON)». Загруженный эталон выбирается
автоматически. При необходимости выберите его в поле «Эталон сравнения».
Загрузка доступна администратору, как в прежнем разделе экспертных эталонов.

Шаг 4. Раскройте «Настроить и запустить сравнение методов». Для первого пилота:
  seed 42; доля обучения 0,7; k 8; минимум HDBSCAN 5;
  вес названия 1; вес атрибутов 2.
Это стартовые настройки для отладки, а не найденные оптимальные параметры.
Выберите конкретный профиль Qwen/DeepSeek или другой LLM. Модель должна быть
доступна в вашей конфигурации. HDBSCAN требует настроенную модель векторизации
(используется существующий сервис embedding, по умолчанию bge-m3).
Перед большим сравнением можно выбрать только k-means: он не вызывает LLM.
Далее запускайте методы последовательно, если ресурсов мало.

Шаг 5. Нажмите «Проверить разметку и разделение H2». Для исходного эталона
и указанных параметров: 100 строк, 74 train, 26 test, 62 конечных категории,
49 одиночных категорий, 13 тестовых позиций с классом, которого нет в train.
Проверка сообщает о неполной разметке, несовпадающих исходниках и возможной
передаче исходной категории модели. Не меняйте seed ради лучшего результата.

Шаг 6. Если эксперт действительно утвердил разметку и дерево, поставьте отметку
«H2: эксперт проверил эталон и зафиксировал дерево до теста». Для предварительного
прогона оставьте её выключенной. Затем нажмите «Запустить сравнение H2: 5 методов».
Кнопка «Пересчитать» выше лишь оценивает уже сохранённые предсказания и не заменяет
запуск лабораторных методов. Дождитесь завершения эксперимента и проверьте статус
каждого метода: ошибку запуска нельзя интерпретировать как нулевую Accuracy.

Шаг 7. В «Сохранённый эксперимент» выберите завершённый прогон. В H2 нажмите
«Отчёт H2: Excel» или «Отчёт H2: JSON». Каждый метод также можно выгрузить отдельно.
История сохраняет разные расчёты; сравнивайте одинаковые базу, эталон, паспорта,
разделение и протокол. Для новой LLM повторите эксперимент с теми же настройками.

6. КАК ЧИТАТЬ ОТЧЁТ H2

H2_сводка — показатели каждого метода, N_correct, N_test, время, интервалы и Δ.
H2_сравнения — три парных сравнения на одних тестовых позициях:
  k-means → полный метод; строки → паспорта; LLM напрямую → HDBSCAN + LLM.
H2_построчно — исходное описание, координаты строки, эталон, предсказание,
  правильность, отсутствие категории, ошибка родителя и причина расхождения.
H2_разделение — все train/test-позиции и группы дублей.
H2_эталонное_дерево — общий каталог категорий с ID и уровнями L1–L3.
H2_соответствие — обученное соответствие кластеров конечным категориям.
H2_связи — предложенные LLM связи родитель–потомок для отдельной проверки экспертом.
H2_методика — определения, параметры, модель и контрольная сумма входов.

Основной вывод по H2 возможен, если полный метод дал Accuracy >= 0,85
и Δ Accuracy к TF-IDF+k-means > 0 на том же закрытом тесте.
При 26 тестовых строках порогу соответствуют минимум 23 верные позиции:
23/26 = 0,8846; 22/26 = 0,8462, то есть ниже порога.
Положительная точечная Δ при доверительном интервале, включающем ноль,
не доказывает устойчивое превосходство. Интервал приводите вместе с разницей.

Не подменяйте главную Accuracy венгерской диагностикой. Без категории — итоговый
отказ; шум — метка HDBSCAN до назначения. Это разные показатели.
Верность связей дерева НЕ равна точности категорий или отсутствию ошибки родителя.
Её проверяют по предложениям LLM до экспертных исправлений: число верных связей /
число проверенных связей. В H2_связи эксперт ставит 1 или 0 и комментарий;
непроверенные связи остаются пустыми. До такой проверки показатель не рассчитан.
Загрузка заполненного листа связей и автоматический пересчёт этого дополнительного
показателя в данной версии не реализованы; основной экспертный Excel сравнивает
категории позиций. Долю верных связей можно посчитать отдельно по оценкам 1/0.

7. ОГРАНИЧЕНИЯ ИМЕННО ЭТОЙ БАЗЫ ИЗ 100 СТРОК

62 класса на 100 строк — очень разреженная выборка, 49 классов встречаются один раз.
При seed=42 половина тестовых строк имеет невиданный в train класс. Поэтому для
методов 1–3 с соответствием, обученным только по меткам train, верхняя граница
Accuracy здесь 13/26 = 50%, даже при отсутствии прочих ошибок. Это свойство выборки,
а не измеренный результат. Для LLM с полным перечнем категорий эта граница не действует.
Сравнение показывает поведение на данном пилоте, но не перенос на все 12 000 строк.
Нельзя сохранять результаты большого теста простым отбором 100 строк без проверки.
Для обобщающего вывода добавьте независимые позиции редких классов, утвердите дерево
и протокол до теста. Не укрупняйте категории только ради достижения 85%.
Порог сходства текстов 60%, использованный для H1, к H2 и H3 не применяется.

8. КАК ИСПОЛЬЗОВАТЬ РАЗМЕТКУ H3

В StockExpert_H3_reference_100.xlsx: 20 синтетических потребностей × 100 позиций,
всего 2 000 пар; первоначально 27 true, 1 973 false, неопределённых null нет.
Потребности ограничены явно указанными текстовыми признаками. Это не подтверждение
физической взаимозаменяемости изделий и не реальные производственные заявки.
Эксперт проверяет «Потребности» и «Пары H3», исправляет relevant_json и reason
на машинном листе «Сопоставление». true — все обязательные признаки совпали,
false — есть противоречие/другой тип, null — данных недостаточно.
Запрос с null не участвует в полном Recall; указывайте число оценённых запросов.

Загрузите EBDZ_100.xlsx как базу, а каждый H3_Qxx.txt отдельно как опросный лист.
Не объединяйте TXT в один документ. Завершите извлечение по базе и потребностям;
для экономии можно использовать готовую базу. Загрузите эталон H3, выберите
тот же завершённый расчёт и запускайте нужные лабораторные методы H3:
BM25, Dense, RRF, каскад с правилами и Cross-Encoder, без правил, полный Cross-Encoder.
Для замера скорости задайте одинаковое оборудование/нагрузку и repeats=3.
SPLADE используйте только при установленной соответствующей модели.
Для сравнения таксономии вкл/выкл используйте отдельные сессии с одинаковыми файлами.

100 < 150: эта база пригодна для отладки, проверки потерь и nDCG@10.
Она не доказывает Recall@150 >= 0,985 и выигрыш p95 на 12 000 позициях.
Выполненные модели, метрики качества и замеры скорости в этот пакет не подставлены.
