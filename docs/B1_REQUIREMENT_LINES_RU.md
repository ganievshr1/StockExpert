# Десять потребностей из одного TXT — 3.9.13-b1.1

В прежней версии регулярные выражения обрабатывали весь опросный лист как одну позицию. Кроме того, после загрузки первого документа интерфейс скрывал добавление следующих файлов. Поэтому файл с десятью наименованиями мог дать всего один паспорт, а список «Сессия с 10 потребностями» оставался пустым.

## Новый режим

В карточке загрузки потребности выберите **«Список позиций — одна строка = одна позиция»**. Режим предназначен для TXT. Каждая непустая строка создаёт отдельную позицию; начальные и конечные пробелы удаляются, пустые строки пропускаются. Режим работает одинаково перед извлечением регулярными выражениями и LLM. LLM не решает, где разделять список.

Например, `fixtures/B1_thermocolumn_10.txt` содержит десять наименований термоколонок из предоставленного файла, с исполнениями от И4 до И13. Он создаёт десять отдельных позиций, которые затем проходят обычное извлечение и нормализацию характеристик. До завершения обработки это ещё не десять готовых паспортов.

Если несколько строк описывают свойства **одного** изделия, оставьте **«Опросный лист — обычный разбор»**. Прежние документы без явного режима обрабатываются по прежним правилам. Для загрузки нескольких отдельных файлов доступен множественный выбор; после первого файла можно добавлять следующие до начала обработки. Замена документа остаётся операцией с одним файлом.

## Проверка B1 на существующей готовой базе

1. Создайте **новую** рабочую сессию, например «B1 — 10 термоколонок».
2. Выберите **«Использовать готовую базу»** и прежнюю нормализованную базу. Установите тот же способ нормализации, модель и состояние переключателя таксономии H2, что использовались для базы. Выбор базы сам по себе не переносит переключатель H2. Повторно загружать и нормализовать все 12 533 складские строки не нужно.
3. В разделе загрузки данных выберите режим **«Список позиций — одна строка = одна позиция»** и файл `Термоколонка10.txt`. Проверьте надпись **«Позиций к загрузке: 10»**, затем нажмите **«Загрузить файл»**. Все десять наименований должны находиться в одном TXT, каждое на своей строке.
4. Нажмите **«Сопоставить с готовой базой»** и дождитесь завершения обработки. Утверждение готовой базы сохраняется; повторное утверждение её классификатора не требуется. Ошибки нормализации нужно устранить до опыта.
5. Откройте **«Для разработчика → Проверка гипотезы B1»**, нажмите **«Обновить конфигурацию»**.
6. В поле **«Сессия с 10 потребностями»** выберите новую сессию. Backend требует не менее десяти паспортов потребностей с `attributes` и утверждённую сессию. Для запуска также нужна совместимая с готовой базой схема и отсутствие активных задач.

Не переиспользуйте для этого уже обработанную сессию, в которой список из десяти строк ранее превратился в один паспорт. Обновление не переписывает сохранённые исходные документы, результаты и историю.

## Установка небольшого исправления на настроенный B1

Дождитесь завершения текущих заданий. Распакуйте `StockExpert_B1_positions_patch.zip` в `/home/ganie/StockExpertB1`. В архиве нет `.env`, Docker volumes или файлов с паролями. Обновляются только код, тесты и документация.

```bash
unzip -o /mnt/c/Users/ganie/Downloads/StockExpert_B1_positions_patch.zip -d /home/ganie/StockExpertB1
cd /home/ganie/StockExpertB1
bash b1-local.sh start shared
```

Эта команда подходит к текущему стенду с общей очередью, интерфейсом `http://localhost:5176` и сохранённым именем проекта `stockexpert-backend`. Для уже используемого режима `split` передайте `start split`. Используйте `b1-local.sh`, чтобы сохранить настройки существующей установки. Выполнять `init`, перенос данных и повторное скачивание моделей не нужно.

После пересборки обновите страницу браузера сочетанием **Ctrl+F5**. Прежние сессии, загруженные модели и пароли остаются в тех же хранилищах.
