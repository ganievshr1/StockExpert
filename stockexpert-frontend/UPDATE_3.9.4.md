# StockExpert 3.9.4 — регулярки для складского Excel на 12 000 строк

Обновлены предоставленные бэкенд и фронтенд 3.9.3. Версия правил — `regex-mtr-v2.0.0`. Регулярные выражения работают на CPU, без LLM, эмбеддингов, классификации H2 и подбора H3. Прежний способ запуска по сохранённой сессии и экспертному эталону остаётся доступным.

## Обновление существующей установки в WSL

Рабочий каталог можно оставить прежним: `/home/ganie/StockExpert3.9.3`. Номер 3.9.4 в именах архивов — версия обновлённого кода.

Сначала дождитесь завершения текущих расчётов. Если архивы скачаны в Windows Downloads пользователя `ganie`, выполните:

```bash
cd /home/ganie/StockExpert3.9.3
cp -n stockexpert-backend/.env stockexpert-backend.env.before-3.9.4
unzip -o /mnt/c/Users/ganie/Downloads/StockExpert_Backend_3.9.4.zip -x 'stockexpert-backend/.env'
unzip -o /mnt/c/Users/ganie/Downloads/StockExpert_Frontend_3.9.4.zip -x 'stockexpert-frontend/.env'
```

Путь к Downloads замените, если файлы находятся в другом месте. Распаковка исключает `.env`, поэтому остаются настройки реально работающей установки. Если первая команда копирования сообщает, что `.env` отсутствует, сначала найдите прежний рабочий `.env`; не создавайте новые пароли для существующего тома PostgreSQL.

Затем обновите и запустите сервисы:

```bash
cd /home/ganie/StockExpert3.9.3/stockexpert-backend
STOCKEXPERT_PROJECT=stockexpert-backend bash scripts/upgrade_preserve_data.sh
cd ../stockexpert-frontend
docker compose -p stockexpert-frontend up -d --build
```

Адрес интерфейса: `http://localhost:5173`.

Скрипт рассчитан на прежний Compose-проект `stockexpert-backend`. Если он у вас другой, укажите его фактическое имя в `STOCKEXPERT_PROJECT`: оно определяет существующий том базы. Скрипт проверяет наличие тома и таблиц, создаёт резервную копию БД и `.env`, выполняет миграцию и сверяет количество исторических записей, включая прежние regex-запуски. При несовпадении проверок обновление останавливается.

Не запускайте `init_env.py`, `reset_stack.py` или `docker compose down -v` для этого обновления. Существующие Docker volumes и пароли должны сохраняться.

## Запуск именно этого файла без LLM

1. Войдите администратором → **Для разработчика**.
2. В блоке **Проверить складской Excel без LLM** выберите `Складские_позиции_12000(3).xlsx` или тот же файл с другим именем.
3. Для извлечения достаточно нажать **Обработать Excel регулярками**. Экспертный эталон и заранее созданная сессия не обязательны.
4. Дождитесь статуса **Завершён**. В истории появятся время, охват правил и число строк для проверки.
5. **Паспорта и ошибки** показывают исходный текст, признаки, цитаты и правила. Есть фильтр **Только строки для проверки**.
6. **Паспорта CSV** выгружает все исходные строки с предприятием, исходной группой, признаками и замечаниями. **JSON** содержит полный снимок и доказательства. Обычный **CSV** выгружает сводку запуска.

Повторный запуск сохраняется отдельной записью. Старые сессии, паспорта LLM, задания, результаты подбора, экспертные оценки и завершённые regex-эксперименты не перезаписываются. Миграция 0008 лишь разрешает пустые ссылки на сессию/эталон для нового способа загрузки. Старые результаты сохраняют прежнюю версию правил и своё содержимое.

## Структура входа

| Столбец | Заголовок | Использование |
| --- | --- | --- |
| A | Предприятие | Метаданные и экспорт |
| B | КИП и средства автоматизации | Исходная группа, только метаданные |
| C | Система | Единственный текст, подаваемый регуляркам |

Первая строка — заголовки, данные начинаются со строки 2. Группа B не считается экспертной классификацией и не подсказывает извлекателю параметры. Идентичные описания в разных строках сохраняются отдельно. Лимит — 20 МБ и 25 000 строк; формулы должны быть заменены исходными текстовыми значениями.

## Что умеют новые правила

- Распознают 31 семейство наименований из файла; сохраняют марки, составные обозначения и дополнительные коды.
- Кабели: количество жил, сечение и напряжение, включая `КПвПпБП-150 3х70-6,0кВ` и префикс `К1-`.
- Датчики: явно заданное давление, резьба `G1/2`, диапазон сигнала `4-20мА` как две границы `0.004–0.020 A`.
- Радиостанции: МГц → Гц, Вт → кВт; другие устройства — явные В/кВ, бар/МПа, IP и климатические исполнения.
- Плиты: тройка размеров с явной единицей → мм, маркировки арматуры/F. Порядок осей не придумывается.
- Шпильки: резьба и поле допуска; склады баллонов: вместимость и газ; привод и присоединение — по явным обозначениям.
- `560MA` в марке двигателя не превращается в ток; `5А` в обозначении насосной установки не превращается в амперы; `М7` внутри модели термостабилизатора не превращается в резьбу.
- Сложные заводские коды сохраняются без приписывания физического смысла числам. Размеры пожарного шкафа без единицы и пара `250х25` у задвижки отмечаются для проверки.

Распознавание марки не означает полного восстановления всех технических параметров. Наименование сохраняется из исходника, произвольная расшифровка сокращений не добавляется. Каждое извлечённое поле имеет цитату, координаты в строке и правило; конфликтные значения не выдаются как однозначные.

## Эксперимент и интерпретация результатов

На предоставленном файле обработаны все **12 000** строк (**9 730** уникальных описаний). В **9 333** строках есть характеристики помимо обозначений; в **2 667** — только марка/код. Всего **8 884** строки имеют замечания для проверки, преимущественно из-за нерасшифрованных заводских кодов. Эти показатели пересекаются: строка может содержать полезные характеристики и одновременно требовать проверки.

Это охват извлечения, а не точность/полнота/F1. Без экспертного эталона качество хранится как `null`, в интерфейсе отображается «Без экспертной оценки». Для оценки загрузите эталон существующего формата, выберите его и включите **Сравнить с выбранным выше эталоном эксперта**. SHA-256 источника и координаты строк должны совпадать. Общие функции сравнения полей и расчёта H1 одинаковы для регулярных выражений и сохранённых LLM-паспортов.

Этот файл использован при разработке правил и помечается в истории как данные разработки. Для независимого сравнения с LLM нужен отдельный размеченный набор; правила следует зафиксировать до итогового прогона.

В среде проверки медиана трёх замеров чистого извлечения 12 000 строк составила **1.505 с**. В реальном запуске проверочного API суммарное время извлечения — **1.922 с**, без чтения Excel, очереди и записи в базу. Это не обещание такого же времени в WSL; сравнивайте методы на одном оборудовании и с одинаковым составом измеряемых этапов.

## Если запуск остаётся в очереди

```bash
cd /home/ganie/StockExpert3.9.3/stockexpert-backend
docker compose -p stockexpert-backend ps
docker compose -p stockexpert-backend logs --tail=100 worker-regex beat
docker compose -p stockexpert-backend up -d --no-deps worker-regex beat
```

Очередь хранится в БД; `beat` публикует новые задания каждые 10 секунд, `worker-regex` исполняет их на CPU. Для этого режима не требуется доступность LLM. Общая проверка готовности всего приложения может отдельно показывать недоступные модельные сервисы.

## Проверка выпуска

Пройдено 203 теста бэкенда и 31 тест фронтенда, выполнена production-сборка. На полном XLSX проверены импорт через API, выполнение worker, сохранение 12 000 результатов, экспорт CSV, пагинация, фильтр проверки и 41 649 ссылок на фрагменты исходного текста. Вызовы функций LLM во время прогона были заблокированы. Все ранее созданные строки тестовой истории остались неизменными. Проверена миграция заполненной базы 0007→0008, включая завершённый результат старой версии правил.

Проверки выполнены на временной SQLite. Docker и PostgreSQL на вашем компьютере здесь не запускались. Подробности: `VALIDATION_3.9.4.md`.
