# Обновление StockExpert 3.2.0

Два парных проекта: FastAPI backend и React frontend. API 3.2.

## Обновление существующей установки

1. Дождитесь завершения текущей обработки. Сохраните резервную копию базы, файлов и `.env`.
2. Распакуйте новые исходники поверх прежних каталогов `stockexpert-backend` и `stockexpert-frontend`. Сохраните прежний `.env`, ключ DeepSeek, пароли и имя Compose-проекта. В архивах нет рабочего `.env`.
3. В прежнем каталоге бэкенда выполните:

```bash
docker compose stop backend worker beat
docker compose build
docker compose up -d postgres redis minio qdrant ollama
docker compose run --rm migrate
docker compose up -d backend worker beat
```

Если миграция завершилась ошибкой, сначала исправьте её; не запускайте рабочие процессы на старой схеме. Миграция 0002 добавляет таблицу времени этапов, сохраняя существующие данные.

4. В прежнем каталоге фронтенда:

```bash
docker compose up -d --build
```

При запуске через Vite: `npm ci`, затем `npm run dev`. Обновите страницу браузера. Не используйте `docker compose down -v`: он удаляет данные томов. Для первого запуска следуйте README; используйте `python3 scripts/init_env.py`.

## Управление сессией

- «Прервать обработку» отменяет очередь сразу; активная задача переходит в CANCEL_REQUESTED, затем CANCELLED на ближайшей контрольной точке. Уже начатая операция модели завершается или достигает таймаута. При недоступном worker остановка ждёт его восстановления; удаление до подтверждения остановки заблокировано.
- Отмена сохраняет файлы и завершённые результаты. Для продолжения можно повторно запустить нормализацию/полный подбор; сохранённые паспорта используются повторно.
- До начала конвейера можно удалить отдельный файл кнопкой возле его имени.
- «Очистить файлы сессии» после подтверждения удаляет ВСЕ файлы источников и отчётов в префиксе сессии, её индекс Qdrant, паспорта, схему, результаты, задания, замеры и старый аудит. Остаются сама пустая сессия и событие очистки. Другие сессии и аккаунты сохраняются. Экспортируйте нужные показатели до очистки.
- При частичной ошибке внешнего хранилища сессия блокируется как CLEANUP_FAILED. Повторите очистку после восстановления сервиса.

## Метрики без эталона

В меню нажмите «Показать вкладку метрик». Вкладку можно скрыть; настройка сохраняется в браузере.

Автоматически считаются по сессии: число строк и паспортов, заполненность каждого признака утверждённой схемы (включая DN, PN, сталь, изоляцию, если они есть), наличие цитат, пропуски, распределение категорий и доля классифицированных строк. Цитата подтверждает наличие источника, но не гарантирует правильность значения.

Для последнего завершённого подбора по каждой потребности показываются число исходных кандидатов, число найденных, shortlist, Top 150, коэффициент сжатия = исходные / Top 150 и сокращение = 1 − Top 150 / исходные. При нулевом знаменателе результат отсутствует, а не подменяется нулём. Размер shortlist по умолчанию во фронтенде — 150.

F1 извлечения, Accuracy категорий и Recall@150 оставлены как «Не измерено». Цели 0.94, 0.85 и 98.5% не являются достигнутыми результатами. Без независимых правильных ответов эти метрики вычислить нельзя; эталон не подключён. Заполненность, наличие цитат и сжатие не выдаются за точность или полноту поиска.

Текущий поиск проекта: Dense + BM25 + RRF → Hard-Rules → Cross-Encoder (если включён). SPLADE не внедрялся. Таксономия предлагается LLM по образцам до нормализации, затем паспорта классифицируются; кластеризация готовых паспортов не реализована.

Время сохраняется отдельно для чтения файлов, схемы/таксономии, разбора потребности, извлечения/нормализации/классификации, векторизации, поиска, правил, Cross-Encoder и сохранения результатов. Нормализация и классификация выполняются одним запросом, поэтому их время не разделяется искусственно. Это прошедшее время этапа, а не сумма длительностей параллельных запросов; ожидание очереди исключено, повторы/ошибки/отмена включены. Старая история 3.1 не получает вымышленные замеры. OCR не добавлен; PDF требует текстового слоя.

«Скачать Excel» выгружает листы «Метрики сессии», «Время этапов», «Сжатие кандидатов». В каждой строке есть ID сессии; временные интервалы содержат ID задания и попытки. Эти листы добавлены и в основной Excel-отчёт.
