# StockExpert 3.9.6

Обновление backend и frontend поверх 3.9.5 с сохранением исправлений из архива H2_fix.

## Что изменено

- При создании сессии и до начала обработки можно отключить H2. H1 создаёт паспорта, H3 ищет без дерева и ограничений по категориям. Характеристики согласуются по точному названию, типу и единице без вызова LLM. На вкладке «Параметры без H2» эксперт выбирает правила сравнения. При отсутствии правил результат требует проверки. Метрика H2 неприменима, а не равна нулю.
- В «Метриках» два независимых дашборда: ручная проверка и загруженный эталон. Источник, версия эталона, запуск, формула и покрытие указаны рядом с результатом. Данные одного источника не вытесняют другой.
- «Сбросить» архивирует выбранную оценку и очищает только её. «Пересчитать» использует сохранённые предсказания, без повторного вызова модели. История позволяет открыть старый запуск, восстановить ручные ответы и пересчитать его оценку.
- Ручная проверка позволяет выбирать старые запуски, открывать проверенные позиции и возвращаться на предыдущую страницу к её последней позиции. На последней позиции переход вперёд больше не возвращает к началу.
- После завершения каждого нового запуска сохраняется снимок паспортов, схемы и исходных координат. Последующие изменения не влияют на пересчёт этого запуска.
- Добавлена очередь лабораторных экспериментов. Они не меняют рабочие паспорта, категории или закупочные решения. Краткая сводка загружается отдельно от больших снимков и предсказаний.
- В рабочем поиске RRF отбирает до 600 кандидатов; после правил список сокращается до выбранного лимита и только затем передаётся Cross-Encoder. Сохраняются ранги до и после Cross-Encoder. Recall@150 измеряется до него, в сохранённом предварительном списке. В старых запусках прежняя семантика отмечена явно.

## Таблицы для презентации

Кнопка «Экспорт таблиц 11 / 16 / 21» выгружает Excel с отдельными листами ручной оценки, загруженного эталона, истории и лабораторных H1/H2/H3. Незапущенные методы показываются как не рассчитанные. Презентация не заполняется вымышленными показателями.

H1: сохранённые паспорта, регулярные выражения, выбранная LLM с проверкой цитат и единиц. Для сравнения Qwen и DeepSeek запускайте один и тот же набор с разными профилями. Дашборд собирает модели с одинаковой разметкой, снимком и разделением в общую таблицу. Измеряются micro-F1, precision, recall и время обработки. У чтения сохранённых паспортов нет вымышленного времени инференса.

H2: TF-IDF + k-means по строкам; векторизация строк + HDBSCAN; векторизация паспортов + HDBSCAN; LLM с фиксированным деревом; HDBSCAN + LLM. Метрики: Accuracy конечной категории, ARI, V-мера, силуэт, доля шума, верность родительской связи там, где дерево есть, прирост к k-means и 95% bootstrap-интервал. У HDBSCAN + LLM именование не меняет сами кластеры, поэтому Accuracy может совпадать с HDBSCAN; дополнительно оценивается иерархия.

H3: BM25; Dense; Dense + BM25 + RRF; RRF + правила без reranker; полный каскад; RRF + Cross-Encoder без правил; Cross-Encoder по всему каталогу; каскад с заменой BM25 на SPLADE. Измеряются средний по запросам Recall@150, nDCG@10, p50/p95, время индекса и потери при извлечении, правилах и сокращении до 150. Интервалы скорости строятся по запросам, повторы одного запроса остаются вместе.

## Протокол эксперимента

1. Завершите H1 или подбор и выберите этот запуск в «Истории запусков».
2. Подготовьте ручную разметку либо загрузите JSON-эталон существующего формата через «Для разработчика». Для H3 нужна полная разметка каталога для каждой оцениваемой потребности, включая позиции вне shortlist.
3. В нужном дашборде раскройте настройки, отметьте методы и задайте seed, долю обучения H2, k, min_cluster_size и повторы запросов. Выберите профиль LLM, если метод его использует.
4. Запустите методы. Не меняйте параметры между сравниваемыми вариантами. Веса, идентификаторы, настройки и входной снимок записываются в историю.
5. После завершения сравните результаты и экспортируйте таблицы. Повторный эксперимент создаёт отдельную запись.

Для H1 и H2 используется одна воспроизводимая тестовая часть. Одинаковые исходные описания остаются в одной части. В H2 кластеризация/дерево обучаются на обучении; Hungarian-соответствие экспертным классам также определяется только на обучении. HDBSCAN использует approximate_predict для новых точек. LLM напрямую создаёт дерево по первым 200 обучающим примерам, а затем назначает его категории всем обучающим и тестовым строкам. Экспертные тестовые метки не передаются моделям. Семантические дубликаты с разным написанием и зависимость источников требуют проверки перед окончательным лабораторным выводом.

Обычная карточка H2 текущей сессии показывает описательную оценку по разметке. Подтверждение гипотезы на закрытом тесте опирается на лабораторную таблицу. Неполные знаменатели не заменяются нулевыми результатами. Порог одной метрики сам по себе не подтверждает всю гипотезу.

H3 запускается на сохранённом каталоге и полностью размеченных запросах. Время индекса/загрузки моделей отделено от времени запроса, один прогрев исключён. Сравнение p95 выполняется внутри одного эксперимента; внешнюю нагрузку сервера необходимо держать одинаковой. База меньше 12 000 позиций и малое число запросов не доказывают выполнение целевого масштаба. Таймер лаборатории исключает запись отчёта в БД. Для каталога из 98 строк Recall@150 не показывает эффективность сокращения до 150.

## Обновление с сохранением данных

Используйте оба архива одной версии. Сохраните действующий `.env`, имя Docker Compose-проекта и существующие тома.

1. Дождитесь завершения текущих заданий и лабораторных экспериментов.
2. Распакуйте код backend в каталог приложения, сохранив `.env` и пользовательские данные.
3. Выполните `bash scripts/upgrade_preserve_data.sh` из каталога backend. Скрипт создаёт резервную копию PostgreSQL и `.env`, проверяет число сохранённых строк и применяет миграцию 0010. Имя проекта должно совпадать с текущим (`STOCKEXPERT_PROJECT`, по умолчанию `stockexpert-backend`).
4. Обновите frontend из второго архива и пересоберите его обычным способом (`npm ci && npm run build` или существующим Docker-развёртыванием).
5. Проверьте существующие сессии и откройте «Метрики». Перезапустите только подбор, если нужен новый Recall до Cross-Encoder; заново нормализовать сохранённые паспорта не требуется.

Не запускайте `docker compose down -v`: удаление томов удаляет данные. Само обновление ничего не развёртывает на вашем сервере автоматически.

Миграция добавляет taxonomy_enabled=True для существующих сессий и таблицы run_snapshots, metric_revisions, lab_experiments. История начнёт записываться новой версией. Для последнего старого запуска можно зафиксировать текущее состояние при первом обращении. Для более старых запусков без снимка доступны сохранённые ручные ответы и результаты поиска; утраченные версии паспортов восстановить нельзя. Сброс метрик сохраняет историю; явная очистка файлов или удаление сессии удаляет и связанную историю.

## Модели и зависимости

- scikit-learn 1.6.1 и hdbscan 0.8.40 добавлены в requirements.txt.
- Dense/HDBSCAN требуют существующую модель эмбеддингов Ollama (EMBEDDING_MODEL).
- Методы LLM используют выбранный существующий профиль. H1 регулярками с отключённым H2 не требует доступности генеративной модели; семантический поиск всё ещё требует модель эмбеддингов.
- Cross-Encoder требует RERANKER_ENABLED=true, ML-зависимости и веса. Если он отключён, соответствующий метод получает явную ошибку, а не подставные оценки.
- Для SPLADE положите совместимые локальные веса MaskedLM в каталог модели, доступный worker, и укажите SPLADE_MODEL_PATH. Автоматическая загрузка SPLADE отключена. В Docker можно использовать существующий том model_cache и путь /models/huggingface/имя-каталога. SPLADE не подменяется BM25.
- Celery beat доставляет лабораторные задания в существующую очередь vector_match. Лабораторные эксперименты исполняются по одному с обновлением блокировки. После сбоя завершённые методы сохраняются, недоставленные/оборванные задания доставляются повторно.

Проверки в этой поставке используют контролируемые фикстуры и заглушки сетевых моделей. Реальные модели, серверная нагрузка и качество на пользовательском экспертном эталоне здесь не измерялись. Числа H1/H2/H3 появятся после запуска в вашей среде.
