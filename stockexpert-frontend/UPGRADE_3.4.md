# StockExpert 3.4 — метрики по экспертной разметке

## Как пользоваться

1. Выполните подбор по новой или повторно используемой базе.
2. В shortlist нажмите «Проверить shortlist для расчёта метрик» либо откройте «Экспертная проверка» в меню.
3. Во вкладке кандидатов отметьте «Подходит» или «Не подходит». Непроверенные пары не считаются ошибками. Для Recall снимите «Только shortlist» и проверьте все пары запуска для выбранной потребности, включая неранжированные и противоречащие позиции.
4. Во вкладке «Параметры и категории» сверяйте исходную строку с паспортом. Отметьте проверенные поля и укажите правильные значения в единицах схемы. Пустое значение означает, что параметр отсутствует в источнике. Если модель пропустила значение, впишите его. Отдельно подтвердите или исправьте категорию.
5. Нажмите «Завершить экспертную проверку». F1, Accuracy, Precision и доступный Recall появятся на рабочем столе, во вкладке метрик и в Excel.

Можно завершить частичную проверку: рядом с результатами будет показан объём выборки. Это показатели проверенных данных, не оценка всех непроверенных позиций. Изменение или удаление отметки сбрасывает завершение; повторно нажмите кнопку завершения.

## Определения

- F1 — micro по явно проверенным полям паспортов: `2 TP / (2 TP + FP + FN)`. Правильно извлечённое непустое значение — TP; ошибочно извлечённое — FP; пропущенное правильное — FN. Неверное непустое значение при непустом правильном даёт одновременно FP и FN. Пара пустых значений не увеличивает TP. При нулевом знаменателе F1 не измерен. Числа сравниваются точно в единицах схемы, строки — с нормализацией пробелов, без нечёткого сравнения марок.
- Accuracy категорий — правильные категории / категории с явным экспертным ответом. «Нет определённой категории» не входит в знаменатель.
- Precision shortlist — подходящие / проверенные кандидаты, входившие в shortlist данного запуска. Это точность на проверенной части shortlist.
- Recall@150 — подходящие позиции с рангом 1–150 / все подходящие позиции, но только для потребностей, у которых проверены ВСЕ сохранённые пары данного запуска. По полностью проверенным потребностям рассчитывается общий micro Recall. Число таких потребностей указано рядом. Непроверенные потребности исключены; при отсутствии подходящих позиций Recall не определён.

В знаменатель Recall входит проверяемая база конкретного запуска, а не все физические складские запасы компании. Оценка охватывает паспорта потребностей и остатков, включая ранее нормализованные и повторно использованные паспорта; это не оценка только текущих вызовов LLM.

## Что сохраняется

Экспертные ответы записываются отдельно от предсказаний модели: quality_reviews хранит исходный ответ, исправление, автора, дату, ID сессии и задания. quality_completions хранит завершение проверки. Есть аудит изменений. Повторный запуск матчинга получает собственную разметку: ответы предыдущего задания автоматически не переносятся.

Исправления в этой форме создают эталон для оценки, но не изменяют рабочие паспорта модели. Иначе сравнение модели с уже исправленным ответом искусственно улучшало бы метрики. Кнопки «Рекомендовать» и «Использовать запас» работают отдельно: оценка «Подходит» не означает списание или резервирование.

Использованные/очищенные позиции остаются доступны для исторической экспертной проверки данного запуска. Очистка файлов сессии удаляет также её разметку и завершения проверки. Простая очистка общей доступности запасов сохраняет историческую разметку.

## Обновление с 3.3

Сохраните резервную копию базы и файлов. Распакуйте бэкенд и фронтенд в прежние каталоги, сохранив свой `.env`, пароли, ключ API и имя Compose-проекта. Дождитесь завершения/отмены активных задач.

В каталоге бэкенда:

```bash
docker compose stop backend worker beat
docker compose build
docker compose up -d postgres redis minio qdrant ollama
docker compose run --rm migrate
docker compose up -d backend worker beat
```

Миграция 0004 добавляет таблицы разметки, не удаляя существующие данные. Если миграция не прошла, исправьте её до запуска рабочих сервисов.

В каталоге фронтенда:

```bash
docker compose up -d --build
```

Для Vite: `npm ci`, затем `npm run dev`. Не используйте `docker compose down -v`. Обновите страницу браузера. Фронтенд и бэкенд должны иметь контракт 3.4.

Повторное использование нормализованной базы, общее наличие запасов, их использование и очистка из версии 3.3 сохранены. Для старых сессий метрики качества появятся после экспертной разметки; старые рекомендации автоматически не считаются эталоном.
