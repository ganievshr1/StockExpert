# Обновление StockExpert 3.4 → 3.5.0

Выпуск состоит из двух совместимых архивов:

- `stockexpert-backend-3.5.0-model-choice.zip` → каталог `stockexpert-backend/`.
- `stockexpert-frontend-3.5.0-model-choice.zip` → каталог `stockexpert-frontend/`.

В них полный исходный код, а не отдельные патчи. Frontend также содержит готовый `dist/`. Установите обе части: контракт изменён на 3.5.

## 1. Сохранение и замена исходников в WSL

Дождитесь окончания активных задач либо отмените их в приложении и дождитесь остановки. При обновлении не запускайте старый worker одновременно с новым.

Из вашего каталога:

```bash
cd ~/stockexpert3.4.0/stockexpert-backend
mkdir -p ../backup-before-3.5
chmod 700 ../backup-before-3.5
cp -p .env ../backup-before-3.5/backend.env
docker compose exec -T postgres pg_dump -U stockexpert -d stockexpert -Fc > ../backup-before-3.5/stockexpert.dump
docker compose stop backend worker beat
```

Проверьте успешное завершение `pg_dump`. Это копия PostgreSQL; исходные документы находятся отдельно в MinIO. Сохраните прежние каталоги исходников перед заменой. При необходимости полного резервирования используйте существующую процедуру резервного копирования Docker volumes / MinIO.

Распакуйте архивы в родительский каталог `~/stockexpert3.4.0`, подтвердив замену исходников. Пример, если ZIP-файлы уже скопированы туда:

```bash
cd ~/stockexpert3.4.0
unzip -o stockexpert-backend-3.5.0-model-choice.zip
unzip -o stockexpert-frontend-3.5.0-model-choice.zip
```

Если ваш фронтенд находится в каталоге с другим именем, перенесите содержимое `stockexpert-frontend/` в его существующий каталог. **Сохраните существующий `.env` бэкенда и прежнее имя Compose-проекта. Не запускайте `docker compose down -v`: это удалит данные.** Секретов `.env` внутри ZIP нет. Для существующей установки `scripts/init_env.py` не нужен и не перезаписывает имеющийся `.env`.

## 2. Настройки моделей

Новые параметры имеют значения по умолчанию и для обновления не обязательны. Можно добавить в существующий `.env`:

```dotenv
# Выбор по умолчанию для новых сессий. Пользователь меняет его в интерфейсе.
LLM_DEFAULT_PROFILE=deepseek
OLLAMA_LLM_CONCURRENCY=1
OLLAMA_LLM_NUM_CTX=16384
OLLAMA_LLM_MAX_TOKENS=4096
OLLAMA_LLM_TIMEOUT=600
```

Если `LLM_DEFAULT_PROFILE` не задан или пуст, сохраняется прежний серверный выбор `LLM_PROVIDER` / `LLM_MODEL`. Уже созданные сессии 3.5 имеют собственный снимок настроек: изменение `.env` не меняет их задним числом. Для новых параметров создайте новую сессию; до первого задания можно заново выбрать профиль, чтобы сохранить его актуальную конфигурацию.

| Вариант интерфейса | `llm_profile_id` | Точный тег / настройка |
|---|---|---|
| Qwen2.5-7B-Instruct Q4 | `qwen25-7b-q4` | `qwen2.5:7b-instruct-q4_K_M` |
| Qwen2.5-7B-Instruct Q5 | `qwen25-7b-q5` | `qwen2.5:7b-instruct-q5_K_M` |
| Qwen3-8B без рассуждений | `qwen3-8b` | `qwen3:8b-q4_K_M`, запрос `think: false` |
| Qwen2.5-14B-Instruct, резерв | `qwen25-14b` | `qwen2.5:14b-instruct-q4_K_M` |
| DeepSeek, внешний API | `deepseek` | `DEEPSEEK_MODEL`; если пусто — прежний `LLM_MODEL` при `LLM_PROVIDER=deepseek` |

Резерв класса 14B конкретизирован как Qwen2.5-14B-Instruct. Q4 и Q5 — отдельные варианты 7B. Идентификатор DeepSeek сохранён из исходного проекта (`deepseek-v4-pro` по умолчанию), его доступность в вашем аккаунте не проверялась. При другом доступном идентификаторе задайте `DEEPSEEK_MODEL`. Ключ — только `DEEPSEEK_API_KEY` бэкенда. `LLM_CONCURRENCY`, `LLM_MAX_TOKENS`, `LLM_TIMEOUT`, `DEEPSEEK_THINKING` и `DEEPSEEK_REASONING_EFFORT` настраивают профиль внешней модели.

## 3. Сборка и миграция бэкенда

```bash
cd ~/stockexpert3.4.0/stockexpert-backend
docker compose build backend worker beat migrate
docker compose up -d postgres redis minio qdrant ollama
docker compose run --rm migrate
docker compose up -d backend worker beat
```

Миграция Alembic `0005` добавляет `procurement_sessions.llm_config`, не изменяя исторические паспорта и результаты. У старых сессий конфигурация помечается как неполная: известные provider/model восстанавливаются из последнего сохранённого runtime, остальные настройки берутся с сервера. Если истории модели нет, используется текущий серверный вариант. Для достоверного сравнения моделей создавайте новые сессии.

## 4. Загрузка весов

Загрузите эмбеддинги и **только те генераторы, которыми будете пользоваться**. Все команды выполняются из каталога бэкенда:

```bash
docker compose exec ollama ollama pull bge-m3
docker compose exec ollama ollama pull qwen2.5:7b-instruct-q4_K_M
docker compose exec ollama ollama pull qwen2.5:7b-instruct-q5_K_M
docker compose exec ollama ollama pull qwen3:8b-q4_K_M
docker compose exec ollama ollama pull qwen2.5:14b-instruct-q4_K_M
docker compose exec ollama ollama list
docker compose exec ollama ollama --version
```

Для DeepSeek скачивать генератор не требуется. Для Qwen3 проверяется Ollama ≥ 0.9.0 и передаётся `think: false`; при появлении непустого `message.thinking` результат отклоняется. JSON и JSON Schema проверяются для всех моделей. При старом локальном шаблоне Qwen3 повторите `ollama pull` его точного тега. В compose сохранена версия Ollama исходного проекта `0.9.0`; образ можно переопределить через `OLLAMA_IMAGE`. Это нижняя граница API, а не гарантия совместимости всех будущих тегов/версий — проверьте небольшую сессию на выбранном образе.

Недоступный вариант можно выбрать заранее. Запуск схемы/нормализации вернёт понятную ошибку, пока модель не загружена или ключ не задан. Автоматического перехода с локальной модели во внешний API нет. Каталог проверяет теги и версию Ollama, а для DeepSeek — только наличие ключа, без платного запроса.

## 5. NVIDIA в WSL2 — при наличии подходящего GPU

Основной compose работает без обязательного GPU. Для передачи NVIDIA GPU в Ollama есть дополнительный файл. Требуется работающая поддержка NVIDIA GPU в Docker/WSL2; память и модель видеокарты автоматически не определяются.

```bash
docker compose -f docker-compose.yml -f docker-compose.gpu.yml up -d ollama
docker compose exec ollama ollama ps
```

После такого запуска используйте оба `-f` при последующем пересоздании Ollama. Q4/Q5 относятся к сжатию весов; дополнительная память нужна для контекста и исполнения. 14B может не поместиться в VRAM ноутбука и работать значительно медленнее с выгрузкой в RAM/CPU. Значения производительности на вашем Victus не измерялись. По умолчанию Ollama держит одну модель и обрабатывает один локальный запрос одновременно.

## 6. Фронтенд

Из существующего каталога фронтенда:

```bash
docker compose up -d --build
```

Бэкенд создаёт сеть `stockexpert-network`, фронтенд подключается к ней. Для запуска без Docker:

```bash
npm ci
npm run dev
```

Откройте http://localhost:5173. Создайте сессию и выберите модель. До первого запуска выбор доступен также на рабочем столе в «Модель анализа». После начала обработки он фиксируется. Для сравнения другой модели создайте новую сессию и при необходимости выберите готовую базу как источник.

## 7. Поведение конвейера и повторное использование

1. Выбранная генеративная модель предлагает схему. Эксперт её проверяет и утверждает.
2. Та же модель выделяет позиции потребности, извлекает признаки и присваивает категории всем обрабатываемым строкам.
3. Поиск сохраняет архитектуру проекта: BGE-M3 → Dense + BM25 + RRF → инженерные правила → Cross-Encoder. Это отдельные специализированные модели; генератор их не заменяет. Текстовые объяснения строятся детерминированно по проверкам.
4. Задание и его повтор используют зафиксированную конфигурацию. Паспорта записываются по мере обработки; повтор не отправляет уже сохранённые паспорта заново.
5. При повторном использовании базы той же конфигурации применяются готовые паспорта. При другой модели либо неизвестном историческом экстракторе копируются доступные исходные строки; требуется новая подготовка и утверждение схемы, затем нормализация. Использованные запасы не возвращаются в доступные.
6. Идентификатор общей складской позиции сохраняется: сессия для сравнения моделей не создаёт новый физический запас. Использование/удаление запаса учитывается во всех связанных сессиях.

Конфигурация фиксирует provider/model/режим/лимиты, но не сохраняет бинарные веса модели и не гарантирует побитовую воспроизводимость после обновления тегов Ollama или внешнего API. Для строго контролируемого эксперимента не обновляйте веса между сравниваемыми запусками и используйте одинаковые данные, схему и экспертную разметку.

## 8. Проверка после установки

Начните с небольшой одинаковой выборки. Проверьте подготовку схемы, извлечение признаков, пропуски, единицы и классификацию, затем вкладку метрик и Excel. Наличие модели и успешный JSON не доказывают качество характеристик. Профиль выбранной модели, время и результаты экспертной проверки позволяют сравнить варианты на вашей выборке.

```bash
docker compose ps
docker compose logs --tail=150 backend worker beat
```

Внешние сервисы и нагрузка 12 000 строк в среде подготовки архива не запускались. Подробности проверок находятся в `VALIDATION.md`.
