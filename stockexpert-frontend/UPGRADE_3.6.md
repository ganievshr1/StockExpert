# StockExpert 3.6.0 — таксономия по нормализованным JSON-паспортам

## Что изменилось

Для новых сессий категория создаётся после нормализации всех позиций. Первое логическое поле паспорта — `name`, нормализованное наименование с цитатой источника. Порядок ключей JSON не определяет поведение программы: всегда читается именно `name`.

1. Подготовка определяет столбцы каждого листа отдельно. Первые десять непустых строк используются только для сопоставления столбцов, а не для категорий. Идентификатор документа и название листа задаёт программа, поэтому модель не должна воспроизводить их.
2. Эксперт утверждает столбцы. Включите наименование и все поля с техническими характеристиками.
3. Каждая позиция остатков и выделенная позиция потребности независимо преобразуется в паспорт: наименование, характеристики, нормализованные единицы, цитаты. Общая потребность не ограничивает набор извлекаемых свойств складской позиции.
4. После завершения нормализации модель анализирует все паспорта партиями до 12 записей и 10 000 символов нормализованного содержимого. Одинаковые нормализованные JSON анализируются совместно; каждая исходная строка сохраняется и получает категорию. Проверяется точное покрытие каждой партии, без пропусков и дублирования идентификаторов.
5. По характерному существительному или устойчивому названию в `name` выделяется родовой тип материала/изделия. Различающиеся названия проверяются на синонимию по всему каталогу, порциями до 24 записей. Разные изделия не должны объединяться только по сырью или похожим параметрам.
6. Внутри каждого материала формируются подкатегории по назначению или конструкции, когда они следуют из наименования. Размеры и марки остаются признаками. Если обоснованного подтипа нет, позиция относится непосредственно к материалу.
7. Набор признаков материала собирается из всех его паспортов. Эквивалентные названия признаков объединяются только при совместимых типе и единице. Признаки разных материалов имеют разные идентификаторы. Конфликт двух значений при объединении останавливает публикацию дерева.
8. Эксперт проверяет группы и настраивает правила сравнения каждого материала, затем утверждает таксономию.
9. Подбор использует признаки соответствующего материала. Разные известные родовые типы исключаются как противоречие. Неизвестная категория, отличающийся подтип или неполные характеристики требуют проверки.

Список типов материалов не зашит в код. Лимит 40 категорий удалён. Техническая защита размера схемы — до 50 000 категорий и признаков. Лимит Excel сохраняется из настроек: `MAX_ROWS=25000`.

## Порядок работы в интерфейсе

Создайте новую сессию → загрузите остатки и потребность → «Подготовить схему» → «Таксономия МТР» → проверьте столбцы → «Утвердить столбцы» → «Нормализовать все позиции и построить категории».

После обработки откройте каждую группу. Проверьте названия, состав позиций, наименования и признаки. По умолчанию все технические правила информационные. Установите необходимые «Равно», «Не менее», «Не более» и допуски: модель не задаёт инженерные ограничения автоматически. Затем нажмите «Утвердить таксономию» и запустите «Полный подбор» на рабочем столе.

Наименование всегда остаётся информационным признаком: оно используется для определения типа изделия, но полные товарные строки не сравниваются на буквальное равенство.

До утверждения таксономию можно перестроить по сохранённым паспортам. Перестроение повторно собирает дерево, используя сохранённые предложения классификации, и сбрасывает отредактированные названия/правила. Для нового извлечения или новой модели нужна новая сессия. Структура групп, единицы нормализованных значений и назначения защищены от произвольной правки JSON; доступны названия и правила сравнения.

## Обновление существующей установки

Обновляйте бэкэнд и фронт совместно: контракт API 3.6.

1. Сохраните резервную копию базы и текущих исходников. Например, из действующего каталога бэкэнда:

   ```bash
   docker compose exec -T postgres pg_dump -U stockexpert stockexpert > stockexpert-before-3.6.sql
   docker compose stop backend worker beat
   ```

2. Распакуйте архивы в отдельное место и перенесите исходники в прежние каталоги проектов. Сохраните действующий `.env`. Не переносите рабочую установку в новый compose-проект, если хотите использовать прежние Docker volumes. Не выполняйте `docker compose down -v`.
3. Из прежнего каталога бэкэнда выполните:

   ```bash
   docker compose up -d --build
   docker compose logs --tail=100 migrate backend worker
   ```

4. Из прежнего каталога фронта выполните:

   ```bash
   docker compose up -d --build
   ```

5. Обновите страницу и создайте новую сессию. Схема PostgreSQL не изменена: новые сведения записываются в существующие JSON-поля. Текущие миграции 0001–0005 остаются в поставке.

Старые сессии с таксономией по образцам сохраняют прежний режим и историю. Повторное использование старой готовой базы с той же моделью также сохраняет старую схему. Чтобы получить новую таксономию, создайте сессию с новой загрузкой Excel; при выборе другой модели для готовой базы исходные строки будут перенесены и обработаны заново.

## Повторное использование новой базы

При совпадении модели и её настроек складские паспорта и утверждённая таксономия копируются. Новая потребность нормализуется и сопоставляется с этим деревом. Категории и признаки автоматически не расширяются в утверждённой базе. Новый неизвестный тип или новое свойство помечаются для проверки; исходные нормализованные значения сохраняются. Для расширения дерева создайте новую сессию с исходным Excel и новой потребностью.

## Устойчивость и границы проверки

Сохранённые паспорта и успешно разобранные партии классификации используются при повторе неудачной задачи. Дерево и итоговые назначения публикуются согласованно. Если модель пропустила позицию, выдала неизвестный идентификатор или при объединении свойств появился конфликт, частичное дерево не утверждается.

Качество смыслового объединения зависит от выбранной LLM; проверка структуры JSON не подтверждает правильность смысла. Для оценки нужны экспертные метрики на ваших данных. Здесь не измерялись качество реальной Qwen/DeepSeek, время на 12 000 позиций и потребление памяти на вашем оборудовании. Модель вызывается для каждой позиции при извлечении; объединение названий и признаков добавляет запросы. Ускорение по сравнению с предыдущей версией не заявляется.

Числовые единицы сохранены из прежнего набора (V, kV, mm, mm2, MPa, bar, m, kg, pcs). Другие единицы и сложные диапазоны сохраняются строкой вместе с единицей; их количественное сравнение требует расширения нормализатора. Разбор потребности сохраняет существующий предел 50 позиций на документ. PDF по-прежнему требует текстового слоя.
