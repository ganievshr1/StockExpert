# StockExpert 3.9.0 — расчёт H1, H2 и H3 по презентации

Обновление от 12 октября 2026 года. Автор проекта: Ганиев Шамиль.

## Где считать

1. Откройте явный пункт меню «Для разработчика» (администратор).
2. Выберите загруженный эталон, отметьте сессии и нажмите «Рассчитать метрики выбранных сессий».
3. Основная таблица показывает ровно H1, H2, H3: процент, формулу с числами, охват и причину отсутствия результата.
4. «Расчёт и ошибки» раскрывает все счётчики и H3 по каждой потребности.
5. На странице «Качество и метрики» выберите тот же эталон. Она показывает ту же сохранённую оценку. Ручная проверка остаётся отдельным источником.
6. Числители, знаменатели и причины отсутствия значений включены в CSV, JSON и лист Excel «H1 H2 H3 по эталону».

Пересчёт метрик не вызывает LLM, не нормализует базу и не изменяет паспорта или результаты матчинга. После установки этой версии старые оценки нужно пересчитать кнопкой из пункта 2. Это только арифметика по сохранённым данным.

## Три формулы

| Метрика | Формула и охват | Цель |
| --- | --- | --- |
| H1 | micro-F1 = 2TP / (2TP + FP + FN). Сначала суммируем все проверенные параметры строк эталона. Ошибочное значение добавляет и FP, и FN; правильный null не добавляет TP. | ≥ 94% |
| H2 | Accuracy L3 = M / N. M — число правильных назначений после взаимно-однозначного сопоставления категорий венгерским алгоритмом; N — все позиции эталона, включая шум и пропуски. | ≥ 85% |
| H3 | Recall@150 = сумма найденных подходящих позиций / сумма всех подходящих позиций во всей базе для размеченных потребностей. Позиции вне выдачи остаются в знаменателе. | ≥ 98,5% |

Формулы соответствуют слайдам 9, 15 и 20–21 презентации «Ганиев Ш.Р._StockExpert_Индивидуальная_презентация v1». Числовые примеры в презентации синтетические, а не результаты сохранённых сессий.

## H3 из общего количества строк

Для каждой размеченной потребности проверяются все N строк базы. При Q потребностях проверяются N × Q пар. Подходящие позиции для разных потребностей учитываются как разные пары; используется общая дробь, а не среднее процентов.

В интерфейсе отдельно показаны:
- все строки базы и число потребностей;
- все пары и число пар с известной релевантностью;
- подходящие во всей базе, найденные в Top 150 и пропущенные;
- Recall@150 — сохранение подходящих позиций;
- доля отбора = число всех кандидатов Top 150 / (N × Q);
- сокращение = 1 − доля отбора.

Пример, не измерение: в 98 строках эксперт определил 3 подходящих позиции. Если Top 150 содержит 2 позиции и обе подходящие, Recall = 2/3 = 66,67%, а доля отбора = 2/98 = 2,04%. Нельзя подменять Recall дробью 2/98 и сравнивать её с целью 98,5%.

## Что требуется для фактических трёх чисел

В примере эталона из проекта 98 строк и одна конкретная потребность: 3 положительные и 95 отрицательных пар. Для другой потребности, например термоколонки вместо кабеля, нужна соответствующая экспертная разметка всех строк. Отсутствие совпадения опросного листа теперь объясняется прямо в карточке H3.

В этом же эталоне категории L3 заданы лишь у 87 из 98 строк. Остальные 11 неоднозначны и требуют уточнения эксперта. Accuracy на 87 размеченных строках остаётся вспомогательной метрикой; основная H2 по всем 98 строкам не подменяется этой величиной. Если сохранённая классификация имеет только два уровня, L3 также нельзя восстановить из общего процента категорий.

Неизвестная релевантность хотя бы одной пары не считается отрицательным ответом и блокирует итоговый Recall всей базы. Дополнительные нормализованные строки вне эталона тоже блокируют утверждение о H3 всей базы; их нужно разметить или уточнить границы набора.

На 98 строках можно измерить Recall@150, но это не подтверждает эксперимент отбора 12 000 → 150. Дополнительные Recall@1/5/10 доступны в расшифровке.

## Установка в WSL с сохранением данных

Завершите или отмените активные задания через интерфейс. Распакуйте оба обновлённых ZIP в `/home/ganie/StockExpert3.9.0` с заменой файлов. Архивы не содержат `.env`; существующий файл и Docker-тома сохраняются.

Выполните одной командой:

```bash
cd /home/ganie/StockExpert3.9.0/stockexpert-backend && docker compose -p stockexpert-backend up -d --wait postgres redis minio qdrant ollama && STOCKEXPERT_PROJECT=stockexpert-backend bash scripts/upgrade_preserve_data.sh && cd ../stockexpert-frontend && docker compose -p stockexpert-frontend up -d --build
```

Скрипт обновления делает резервную копию. При незавершённых заданиях он останавливается: завершите их в интерфейсе и повторите команду. Новых миграций для этого изменения нет. Не удаляйте Docker-тома. После запуска нажмите Ctrl+F5 и пересчитайте метрики выбранных сессий; повторная обработка базы не нужна.
