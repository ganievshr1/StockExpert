# StockExpert 3.3 — общая база остатков и эффективность

## Первый запуск с новым Excel

Создайте сессию → «Загрузить новый Excel» → загрузите остатки и опросный лист → подготовьте и утвердите схему → «Полный подбор».

Сразу после загрузки Excel его исходные строки записываются в PostgreSQL (items.raw), исходный файл сохраняется в MinIO. После утверждения схемы нормализованные паспорта записываются в PostgreSQL (items.passport), создаются общие записи наличия stock_positions. Далее строится индекс Qdrant и выполняется матчинг. Исходные строки не отправляются на повторную нормализацию при повторном использовании базы.

## Следующие опросные листы без Excel

1. «Новая сессия» → «Складская база» → «Использовать нормализованную базу».
2. Выберите исходную сессию с готовыми остатками. В списке доступны полностью нормализованные базы вашей организации без активной обработки, с хотя бы одной доступной позицией.
3. Загрузите только новый опросный лист.
4. Нажмите «Подобрать по новой потребности».

Готовые паспорта и утверждённая схема используются повторно. Модель разбирает и нормализует только новую потребность. Совместимые векторы выбранной базы переиспользуются; отсутствующие либо несовместимые с текущей моделью векторы строятся заново без повторного извлечения свойств остатков. Старый индекс 3.2 не содержит метаданных совместимости, поэтому векторы могут однократно пересчитаться.

Сессия получает собственную копию исходных документов и паспортов для истории, но все копии одного запаса ссылаются на общую запись stock_positions. Это сохраняет историю при очистке файлов исходной сессии и синхронизирует доступность запаса. Отдельно загруженные Excel считаются разными базами; автоматического отождествления одинаковых позиций между независимыми загрузками нет.

Сохраняются признаки, категории и правила исходной схемы. Если новый опросный лист требует новых признаков, которых нет в готовых паспортах, создайте новую базу с соответствующей схемой и выполните нормализацию.

## Использование запаса

В shortlist сохраните решение эксперта «Рекомендовать к использованию», затем нажмите «Использовать запас» и подтвердите.

Позиция целиком помечается USED в общей базе и исключается из текущих shortlist и будущего матчинга ВСЕХ связанных сессий. Повторное использование блокируется условным обновлением в PostgreSQL, даже если второй пользователь открыл устаревшую страницу. Технически противоречащие позиции использовать нельзя. В режиме всех пар остаётся историческая запись с отметкой «Запас использован».

Это учёт доступности внутри StockExpert. Частичное списание количества и запись в ERP не реализованы. Рекомендация сама по себе не списывает запас; для этого нужно отдельное действие «Использовать запас».

## Очистка базы и новый Excel

«Очистить общую базу» исключает все её доступные позиции из активного подбора во всех связанных сессиях (состояние CLEARED). Если в связанных сессиях идёт обработка, сначала отмените её. История документов, паспортов и решений сохраняется для просмотра. Аккаунты и независимые базы других загрузок не удаляются.

После очистки нажмите «Новая сессия» → «Загрузить новый Excel». Для физического удаления файлов и результатов конкретной сессии есть отдельная кнопка «Очистить файлы сессии». Она удаляет файлы, паспорта, результаты, задания и метрики этой сессии; уже созданные копии в других сессиях остаются. Очистка файлов и очистка общей доступности — разные действия.

## Автоматические метрики

После завершения подбора на рабочем столе автоматически раскрывается «Результаты и эффективность сессии». Показываются:

- время последнего подбора и общее измеренное время обработки с повторными попытками;
- количество повторно использованных паспортов и вновь нормализованных остатков/потребностей;
- повторно использованные и вновь созданные векторы;
- число потребностей с кандидатами, пары до отбора, shortlist и Top 150;
- коэффициент сжатия = пары до отбора / Top 150, сокращение = 1 − Top 150 / пары до отбора;
- доля противоречий и число пар Top 150, прошедших известные правила;
- текущая доступность запасов и shortlist с учётом использования и очистки.

Исторические показатели подбора сохраняются, текущая доступность отображается отдельно. Вкладка метрик содержит заполненность параметров, цитаты, категории и время этапов. Excel включает показатели эффективности, ID сессии, задания и попытки. Копирование базы измеряется отдельно в base_copy_seconds; ожидание очереди в processing_seconds не включается. Счётчики новых паспортов доступны для запусков 3.3; при отсутствии старых замеров показывается прочерк.

F1, Accuracy и Recall@150 требуют независимого эталона, который пока не подключён. Они остаются «Не измерено». Охват потребностей кандидатами не равен Recall, а отсутствие противоречий не доказывает пригодность изделия. Финансовая экономия и стоимость API не выдумываются.

Текущий алгоритм: Dense + BM25 + RRF → Hard-Rules → Cross-Encoder (если включён); SPLADE не добавлен. Таксономия формируется по образцам перед нормализацией, затем выполняется классификация.

## Обновление с 3.2 без удаления данных

Сохраните резервную копию базы и файлов, дождитесь остановки заданий. Распакуйте исходники поверх прежних каталогов, сохранив свой `.env`, пароли, ключи и имя Compose-проекта.

В каталоге бэкенда:

```bash
docker compose stop backend worker beat
docker compose build
docker compose up -d postgres redis minio qdrant ollama
docker compose run --rm migrate
docker compose up -d backend worker beat
```

Миграция 0003 добавляет метаданные базы, таблицу stock_positions и связь запасов. Если миграция завершилась ошибкой, исправьте её до запуска worker. Существующие нормализованные базы доступны без повторной нормализации; общие записи наличия создаются при первом использовании/копировании/подборе.

В каталоге фронтенда:

```bash
docker compose up -d --build
```

Для Vite: `npm ci`, `npm run dev`. Обновите страницу. Не выполняйте `docker compose down -v`, чтобы не удалить тома. Первичная установка описана в README; для генерации нового окружения используйте `python3 scripts/init_env.py`.
