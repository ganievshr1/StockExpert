StockExpert 3.9.8 — выгрузка результатов и видимый выбор H2

УСТАНОВКА В WSL

Скачайте StockExpert_3.9.8_exports.zip в загрузки пользователя ganie.
При запущенном Docker Desktop выполните в Ubuntu одной командой:

mkdir -p /home/ganie/StockExpert3.9.8 && unzip -oq /mnt/c/Users/ganie/Downloads/StockExpert_3.9.8_exports.zip -d /home/ganie/StockExpert3.9.8 && bash /home/ganie/StockExpert3.9.8/install_update.sh

Если архив сохранён в загрузки Ubuntu, замените путь к архиву на
/home/ganie/Downloads/StockExpert_3.9.8_exports.zip.

Обновление использует существующий Docker-проект stockexpert-backend,
его базу, модели и настройки. Создаётся резервная копия БД. Активные
расчёты нужно закончить перед обновлением. Новых миграций для 3.9.8 нет.
После запуска откройте http://localhost:5173 и нажмите Ctrl+F5.
Само развёртывание на вашем компьютере из этой среды не выполнялось.

ГДЕ ВЫБРАТЬ H2

1. «Новая закупочная сессия» → «Режим H2 — таксономия».
2. Для созданной сессии: «Данные» → тот же видимый блок.
   Он также есть в настройках сессии.

«С H2 — построить категории»: H1 → дерево H2 → поиск H3.
«Без H2 — сразу к поиску»: H1 → поиск H3 по описаниям и параметрам.
Без H2 дерево не ограничивает поиск и метрики H2 не рассчитываются.
Режим фиксируется после начала обработки. Для другого режима создайте
новую сессию. Настройка уже обработанного запуска задним числом не меняется.

ВЫГРУЗКА РЕЗУЛЬТАТОВ H1/H2/H3

«Метрики» → «История запусков» → выберите нужный завершённый запуск →
«Скачать результаты выбранного расчёта» → этап → «Скачать JSON/Excel».
На странице обзора сессии есть переход «Скачать результаты расчёта».

H1: source_text, исходные ячейки, name, извлечённые параметры, единицы,
цитаты и идентификатор модели. Категории H2 в этот раздел не включены.
H2: сохранённое дерево, категория и путь каждой позиции.
H3: все сохранённые пары запроса и МТР, ранги, признаки shortlist,
результаты сопоставления. Несохранённые движком пары не восстанавливаются.
«Все сохранённые этапы» объединяет доступные результаты в одном файле.

По умолчанию H1/H2 выгружают только складские МТР. Для вашей базы это
99 строк. 30 строк опросного листа не прибавляются к ним автоматически.
В выпадающем списке можно выбрать только опросный лист или оба источника.
Количество не зашито в код: для другой базы выгружаются её строки.
Повторяющиеся описания разных строк сохранены как отдельные позиции.
Позиция без паспорта сохранена с status=missing и name=null.

JSON H1: массив passports. В каждой записи:
  source_sha256 / sheet / row / kind — ключ для сопоставления с эталоном;
  item_id — ID позиции внутри сессии;
  source_text — текст на входе;
  name — распознанный текст;
  attributes / raw_attributes / features / evidence — параметры и цитаты.
run.job_id, run.created_at, run.normalization_method, run.taxonomy_enabled
показывают, из какого запуска получены значения.

В экспертном файле паспорта могут иметь ID R001, R002 и т. п.; для
сравнения между сессиями используйте ключ из четырёх полей, а не item_id
или id. Для H1 «только текст» сравнивайте только name после удаления
пробелов по краям. Категории и технические параметры не входят в эту
метрику. Полная методика — README_H1_TEXT_99.txt. Сам эталон сохранён
без изменений: expert_reference_H1_text_99.json.

Excel: отдельные листы H1_тексты, H1_параметры, H2_дерево, H2_позиции,
H3_пары в зависимости от выбранного этапа. На листе «Расчёт» — ID и
настройки запуска, на «Источники» — файлы. «Данные_JSON» содержит полный
эквивалент JSON, разбитый на части: длинные значения можно восстановить,
склеив json_chunk в порядке part. Тексты не исполняются как формулы Excel.

ЛАБОРАТОРНЫЕ МЕТОДЫ И СОХРАНЁННЫЕ ОЦЕНКИ

В ручном или автоматическом дашборде выберите «Сохранённый эксперимент»
и нажмите «Эксперимент: JSON/Excel». Будут выгружены все выполненные
методы с предсказаниями, метриками и источником эталона. В подробностях
каждого метода есть «Метод: JSON/Excel» для отдельной выгрузки.
Ключи predictions связываются с item_id в rows; для H3 ключ — ID запроса.
H1/H2 лабораторного эксперимента могут содержать только тестовую часть.
Для всей базы используйте выгрузку результатов запуска, описанную выше.

«История оценок и пересчётов» → «Открыть» → «Оценка: JSON/Excel»:
сохранённая версия метрик и ручные ответы, если это ручная проверка.
source=manual и source=automatic явно разделяют происхождение оценки.
Выгрузка ничего не пересчитывает и не меняет сохранённые ответы.
Прежняя кнопка «Экспорт таблиц 11 / 16 / 21» выгружает сводные метрики.

ИСТОРИЯ И ОГРАНИЧЕНИЯ

Для новых запусков сохраняются паспорта, категории и пары H3. При
выгрузке старого расчёта текущие результаты не подставляются вместо них.
В старых снимках 3.9.6/3.9.7 H3 берётся из записей именно выбранного job_id;
поле h3.source показывает frozen_snapshot или job_match_records.
Если снимок очень старого запуска отсутствует, выгрузка сообщит об этом.
Для последнего старого запуска может фиксироваться состояние на момент
обновления; это явно отмечается legacy_capture=true.
Эксперименты выгружаются после завершения; при ошибке доступны уже
сохранённые частичные результаты со статусом каждого метода.

API И КОМАНДНАЯ СТРОКА

GET /api/v1/runs/{session_id}/{job_id}/export
  ?stage=h1|h2|h3|all&format=json|xlsx&item_kind=residual|requirement|all
GET /api/v1/laboratory/{session_id}/experiments/{experiment_id}/export
  ?format=json|xlsx&method=ID_МЕТОДА
GET /api/v1/laboratory/{session_id}/history/{revision_id}/export
  ?format=json|xlsx

Все API-выгрузки требуют авторизацию и проверяют доступ к сессии.
Внутри backend доступен CLI (stdout — содержимое файла):
python scripts/export_predictions.py SESSION_UUID --job JOB_UUID --stage h1 > h1.json
python scripts/export_predictions.py SESSION_UUID --job JOB_UUID --stage all --format xlsx > results.xlsx
CLI теперь выдаёт полноценный JSON вместо старого JSONL только с атрибутами.

ПРОВЕРКИ ПОСТАВКИ

16 тестов backend: выгрузки, снимки истории, H1 по 99 текстам, лаборатория,
отделение опросного листа, пропущенные ответы, доступ к сессиям, Excel.
15 тестов frontend: выбор и блокировка H2, разные источники оценок,
выгрузка выбранного старого запуска и сохранённого эксперимента.
Сборка TypeScript/Vite. Проверка синтаксиса установочного скрипта.
Тесты проверяют поведение программы; качество LLM на реальной базе
не измерялось и результаты экспериментов не подставлялись.
