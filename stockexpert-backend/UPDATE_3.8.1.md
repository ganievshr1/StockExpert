# StockExpert Backend 3.8.1 — восстановление классификации H2

Исправлена остановка задания с `ValueError: Taxonomy must cover every normalized passport in the batch exactly once`.

## Причина

H1 уже сформировал нормализованные паспорта. H2 отправлял модели до 12 уникальных паспортов за запрос и требовал строго один ответ на каждый `item_id`. Пропущенный, изменённый, посторонний или повторный ID приводил к исключению всего пакета. Одинаковые паспорта представлены одним ID и числом исходных строк `source_rows`; модель не должна повторять ответ по этому числу.

По одной строке ошибки нельзя определить конкретную позицию или установить, что именно вернула модель. В 3.8.0 ошибочный ответ H2 не сохранялся перед этим исключением. В 3.8.1 есть структурированная диагностика новых попыток.

## Новое поведение

1. В запросе перечислены необходимые ID; JSON Schema ограничивает допустимые ID и число ответов размером текущего пакета.
2. Ответ разбирается по ID, независимо от порядка. Принимаются только валидные классификации с известным ID, встречающимся ровно один раз. Посторонние ID отбрасываются; неоднозначные дубликаты не выбираются произвольно.
3. Правильные классификации сохраняются сразу. Повторные запросы содержат только неразобранные позиции, по одной позиции на запрос, и диагностику предыдущей ошибки.
4. Общее число попыток на позицию ограничено `TAXONOMY_MAX_ATTEMPTS` (по умолчанию 3, диапазон 1–5). Существующий `.env` менять не требуется. Сетевые повторы провайдера регулируются отдельно.
5. После исчерпания попыток паспорт и все подтвержденные характеристики сохраняются; позиция направляется в «Требует проверки». Слишком большой для классификационного контекста паспорт также сохраняется для проверки, без усечения характеристик.
6. Для одинаковых паспортов результат переносится на каждую исходную строку. Число строк и их источники сохраняются; каждую строку можно проверить отдельно.
7. При подборе отсутствие достоверной категории не превращается в автоматическое соответствие и само по себе не отсекает позицию из-за несовпадения категорий. Проверенные противоречия по характеристикам остаются значимыми.

Сохранённые H1-паспорта и принятые классификации повторно не запрашиваются при возобновлении задания. Обычный повтор использует также сохранённые результаты «Требует проверки». Для повторной попытки классифицировать именно эти позиции до утверждения таксономии используйте существующее действие перестроения: `POST /api/v1/taxonomy/{sid}/rebuild`. Оно повторяет H2 для неразобранных позиций, сохраняя успешные предложения и H1. В утверждённой базе новая неразобранная потребность остаётся без категории и требует проверки.

Ошибки сети, авторизации провайдера, базы и программирования не маскируются. Если такая ошибка возникает во время исправляющего запроса, уже принятые классификации остаются сохранёнными. Прочие инварианты таксономии, включая проверку объединения характеристик и идентификаторов каталога, сохраняются.

## Диагностика

В паспорте добавлен блок `classification`: `status`, `requires_review`, `attempts`, `errors`, `representative_item_id`, `raw_response` (принятая классификация). `normalization` описывает отдельно результат H1 и не подменяется состоянием H2.

В `errors` доступны `missing_ids`, `duplicate_ids`, `unexpected_ids`, `invalid_ids`, ожидаемое и полученное число записей, номер попытки и, если есть, ошибка схемы/JSON. Замечание `TAXONOMY_NEEDS_REVIEW` содержит исходное наименование и координаты источника, сохранённые при H1.

`GET /api/v1/pipeline/{sid}/normalization-review` теперь возвращает позиции, требующие проверки H1 **или** H2. Пагинация и изоляция организаций сохранены. В параметрах задания добавлен `taxonomy_review_count`.

Существующий фронтенд показывает категорию «Требует проверки» и код замечания. Подробная диагностика доступна через API/Swagger; фронтенд в этом архиве не изменялся. Новые таблицы и миграции не требуются.

## Обновление в WSL без очистки базы

Скачайте `stockexpert-backend-3.8.1.zip` в `C:\Users\ganie\Downloads`. Дождитесь завершения других работающих заданий перед перезапуском worker. Затем выполните целиком:

```bash
bash <<'BASH'
set -euo pipefail
stockexpert_root="/home/ganie/StockExpert3.8.0"
stockexpert_zip="/mnt/c/Users/ganie/Downloads/stockexpert-backend-3.8.1.zip"
test -f "$stockexpert_zip"
test -f "$stockexpert_root/stockexpert-backend/.env"
unzip -o "$stockexpert_zip" -d "$stockexpert_root"
cd "$stockexpert_root/stockexpert-backend"
docker compose -p stockexpert-backend build backend worker beat migrate
docker compose -p stockexpert-backend up -d --no-build --pull never
docker compose -p stockexpert-frontend -f ../stockexpert-frontend/docker-compose.yml restart frontend
BASH
```

Архив не содержит `.env` и данных БД. Эти команды не удаляют тома, пользователей, пароли, загруженные модели и результаты. Папка установки остаётся `StockExpert3.8.0`, версия кода внутри становится 3.8.1.

После обновления откройте прежнюю сессию и нажмите **«Повторить задачу»**. Нормализованные паспорта сохранятся; продолжится построение категорий.

Для этой ошибки не запускайте `reset_stack.py --yes`, прежние команды удаления томов или `down -v`: очистка не требуется.

Проверка установленной версии:

```bash
curl -f http://localhost:8000/
docker compose -p stockexpert-backend logs --no-color --tail=100 worker
```
