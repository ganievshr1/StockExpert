# StockExpert 3.9.5 — исправление H2

Версия API: `3.9.5-h2fix.1`. Дата: 18 октября 2026.

## Причина и исправление

Ошибка `Conflicting normalized attributes merged by taxonomy` возникает,
когда H2 сопоставляет разные исходные признаки одному полю таксономии,
а их значения в одном паспорте различаются. До исправления это прерывало
всю задачу. Для конкретного UUID из сообщения пользователя нет доступа
к локальной базе WSL; названия конфликтующих признаков не устанавливались.
Механизм ошибки воспроизведён в тестах на строках кабеля с основной
и дополнительной группами жил.

- Разные ключи регулярного движка сохраняются раздельно: словарь H1 уже
  определяет смысл каждого ключа. Ограничение действует и при одинаковых
  значениях, и при наличии признаков в разных строках.
- Для свободных признаков LLM H2 исключает объединения, которым противоречат
  значения, совместно встречающиеся в паспортах. Проверяются все участники
  группы синонимов, а не только её первое название.
- В утверждённой базе нельзя незаметно расширять схему. Если сопоставление
  новых характеристик конфликтует, итоговое поле получает `null`, исходные
  признаки и цитаты H1 сохраняются. Замечание `TAXONOMY_FIELD_CONFLICT`
  содержит ключи, значения и доказательства; строка доступна через API
  проверки паспортов и требует проверки при подборе H3.
- Совпадающие допустимые синонимы сохраняют доказательство непустого значения.
- Политика сопоставления фиксируется в паспорте и параметрах задания:
  `distinct-regex-keys-and-observed-conflicts-v1`.

H2 продолжает использовать выбранную модель для классификации изделий.
Регулярные выражения работают на этапе H1. Правила H1, адаптер и их хеши
остались прежними, поэтому ранее созданную задачу можно повторить.

## Установка в существующую 3.9.5

Скачайте `StockExpert_Backend_3.9.5_H2_fix.zip` в
`C:\Users\ganie\Downloads`, затем выполните в Ubuntu (WSL):

```bash
unzip -o /mnt/c/Users/ganie/Downloads/StockExpert_Backend_3.9.5_H2_fix.zip -d /home/ganie/StockExpert3.9.5 -x 'stockexpert-backend/.env' &&
cd /home/ganie/StockExpert3.9.5/stockexpert-backend &&
STOCKEXPERT_PROJECT=stockexpert-backend bash scripts/upgrade_preserve_data.sh
```

Это полный обновлённый код бэкенда. Рабочий `.env` не включён в архив:
используется файл из установленной версии. Скрипт обновления проверяет
отсутствие активных заданий, делает резервную копию базы и `.env`, пересобирает
контейнеры и сохраняет прежние тома. Новых миграций в этом исправлении нет.
Если другой расчёт ещё выполняется, завершите или отмените его через
интерфейс и повторите обновление.

Фронтенд 3.9.5 совместим с исправлением; его переустановка не требуется.
После успешного обновления откройте прежнюю сессию с ошибкой и нажмите
«Повторить задачу». H2 использует уже сохранённые паспорта и успешные
предложения классификации. Повторно загружать Excel или запускать H1 не нужно.
Завершённые исторические сессии автоматически не пересчитываются.

Проверить установленную версию:

```bash
curl -fsS http://localhost:8000/
```

В ответе должно быть `"version":"3.9.5-h2fix.1"`.

## Проверка исправления

- В прежнем коде воспроизведён тот же `ValueError` через основной API и worker.
- 214 тестов бэкенда прошли, включая шесть новых регрессионных проверок.
- Проверен повтор FAILED → QUEUED → COMPLETED: H1 и его завершённое задание
  остаются прежними, успешные предложения классификации используются повторно.
- Проверены конфликты утверждённой базы, выдача замечания через API, результат
  H3 `NEEDS_REVIEW` и сохранность исходной и скопированной складской базы.
- Полный исходный файл: 12 000 складских строк + 1 потребность прошли H1 → H2
  в основном API/worker, итог `TAXONOMY_REVIEW`. Все значения и цитаты H1
  сохранены, новых вызовов H1 на этапе H2 нет. Проверено 41 649 цитат склада.
- Результаты исторической контрольной сессии остались неизменными.
- Проверены целостность ZIP, контрольные суммы и неизменность правил H1,
  адаптера, миграций, зависимостей и Docker Compose относительно 3.9.5.

Проверочная среда: временная SQLite; Redis/MinIO заменены тестовыми
реализациями. Ответы H2 контролировались тестом, в том числе намеренно
предлагалось неверное объединение. Это проверка устойчивости движка,
а не оценка качества или скорости живой Qwen. Docker/PostgreSQL в WSL
пользователя здесь не запускались.
