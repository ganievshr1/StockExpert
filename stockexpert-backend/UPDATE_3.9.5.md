# StockExpert 3.9.5 — регулярные выражения в основном движке H1

В версии 3.9.4 регулярки запускались отдельным экспериментом. В 3.9.5 они встроены в основной этап H1 закупочной сессии. Результат — обычные JSON-паспорта в таблице `items`, которые использует H2, поиск H3, просмотр качества и существующий расчёт метрик по экспертному эталону.

## Как запустить через основной интерфейс

1. Создайте **новую закупочную сессию**. В поле **«Метод H1 — извлечение характеристик»** выберите **«Регулярные выражения · CPU»**. Это значение уже выбрано по умолчанию в новой форме.
2. Поле **«Модель H2 — классификация паспортов»** относится к следующему этапу. Его можно менять до начала H2. Недоступность Qwen/DeepSeek не блокирует подготовку и отдельный запуск H1 регулярками.
3. Выберите **«Загрузить новый Excel»**, загрузите складской файл и опросный лист TXT.
4. Нажмите **«Продолжить»** и утвердите столбцы. Для предоставленного файла определяется C «Система». A и B не подаются регуляркам. Для другого формата внимательно проверьте предлагаемое соответствие столбцов.
5. Нажмите **«H1: нормализовать регулярками»**. Основной worker создаст паспорта без вызова LLM и сохранит их в этой сессии. Статус станет **«H1 завершён: паспорта готовы»**.
6. Если нужен только эксперимент H1, откройте **«Для разработчика»**, загрузите/выберите соответствующий экспертный эталон, отметьте новую сессию и нажмите **«Рассчитать метрики выбранных сессий»**. Используется обычный расчёт метрик сохранённых сессий. Повторный запуск извлечения для этого не нужен.
7. Для продолжения нажмите **«H2: построить категории»**. H2 использует выбранную модель и готовые паспорта регулярок. Затем проверьте/утвердите классификатор и запустите подбор H3.

В управлении сессией также есть **«Только H1: регулярки»** и совместный запуск **«H1 регулярками + H2 моделью»**. Совместному запуску нужна доступная модель H2. Отдельному H1 она не нужна.

При выборе **готовой базы** её старые паспорта сохраняются, даже если для новой потребности выбран другой метод H1. Поэтому для сравнения регулярных выражений с прежним Qwen на складских строках нужно создать новую сессию и загрузить тот же исходный Excel. Старую сессию не удаляйте — она останется для сравнения.

## Обновление в вашем каталоге WSL

Можно оставить текущую папку `/home/ganie/StockExpert3.9.4`; версия кода внутри станет 3.9.5. После загрузки двух архивов в `C:\Users\ganie\Downloads` выполните в Ubuntu:

```bash
cd /home/ganie/StockExpert3.9.4 &&
unzip -o /mnt/c/Users/ganie/Downloads/StockExpert_Backend_3.9.5.zip -x 'stockexpert-backend/.env' &&
unzip -o /mnt/c/Users/ganie/Downloads/StockExpert_Frontend_3.9.5.zip -x 'stockexpert-frontend/.env' &&
cd stockexpert-backend &&
STOCKEXPERT_PROJECT=stockexpert-backend bash scripts/upgrade_preserve_data.sh &&
cd ../stockexpert-frontend &&
docker compose -p stockexpert-frontend up -d --build
```

Сохраните прежний `.env`, Compose-проект `stockexpert-backend` и Docker-тома. Скрипт обновления проверяет отсутствие активных заданий, делает резервную копию базы и `.env`, выполняет миграцию 0009 и сверяет исторические счётчики. Для обновления не нужны `init_env.py`, сброс базы или `down -v`.

После запуска откройте `http://localhost:5173` и обновите страницу Ctrl+F5. Если скрипт обнаружил незавершённые задания, дождитесь их окончания либо отмените через интерфейс и повторите обновление.

## История и воспроизводимость

- Миграция 0009 добавляет поле метода H1. Все прежние сессии сохраняют `llm`; их паспорта, задания, оценки и результаты подбора не пересчитываются.
- Старые задания без нового снимка метода продолжают использовать LLM. Новые задания сохраняют метод H1, версию/хеш правил и версию/хеш адаптера движка. Изменившиеся правила не подставляются молча при повторной доставке задания.
- Метод H1 фиксируется после его запуска; для другого метода создаётся новая сессия. Модель H2 фиксируется отдельно при начале её использования.
- Паспорт хранит `provider=regex`, `llm_calls=0`, цитаты, правила и исходные координаты. H2 дополняет паспорт классификацией, сохраняя исходный результат H1 и его происхождение.
- Старый отдельный эксперимент 3.9.4 и его история остаются доступны, но для основной обработки используется выбор метода H1 в сессии.

## Ограничения и корректная оценка

Регулярки сохраняют неизвестные коды и отмечают неоднозначные характеристики для проверки. Оговорки по параметрам не мешают H2 классифицировать изделие по подтверждённому названию. При подборе сохраняется отметка о необходимости проверки.

В режиме регулярок опросный лист сохраняется одной позицией. Многострочный текст получает замечание для ручной проверки: строки параметров не делятся произвольно на отдельные изделия. Для нескольких независимых потребностей используйте отдельные опросные листы/сессии. Это ограничение детерминированного разбора, не вызов LLM под другим названием.

Без экспертного эталона Precision/Recall/F1 не вычисляются. После одного H1 показатели H2 и H3 остаются пустыми до выполнения соответствующих этапов. Файл на 12 000 строк использовался для настройки правил; для независимой оценки необходим отдельный размеченный набор.

В новой форме по умолчанию выбран `regex`. Для совместимости старых API-клиентов отсутствие `normalization_method` в запросе создания сессии сохраняет прежний режим `llm`. Явный запрос для регулярок: `{"title":"H1 regex","normalization_method":"regex","llm_profile_id":"qwen3-8b"}`.

## Проверка

208 тестов бэкенда и 35 тестов фронтенда; production-сборка. Проверена цепочка «H1 регулярками → H2 → подбор» с тестовыми ответами модели H2, проверены обычные H1-метрики, изоляция организаций, запрет смены метода после старта, сохранность старых строк, повторное использование баз и миграции.

Все 12 000 строк вашего Excel проведены через основной API сессий и настоящий worker H1. Сохранено 12 000 складских паспортов и один паспорт потребности, проверено 41 649 цитат, вызовов LLM — 0. Прежние записи тестовой базы не изменились. Проверочный запуск H1 с сохранением в SQLite занял около 13,4 с; это не чистое время регулярных выражений и не прогноз для WSL.

Проверки выполнены в изолированной SQLite, хранилище файлов и Redis заменялись тестовыми реализациями. Docker/PostgreSQL на вашем компьютере здесь не запускались. Подробный протокол: `VALIDATION_3.9.5.md`.
