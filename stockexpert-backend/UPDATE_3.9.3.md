# StockExpert 3.9.3 — эксперимент нормализации регулярными выражениями

Основа: предоставленный архив StockExpert3.9.1. Добавлен отдельный эксперимент H1: «регулярные выражения + фиксированные словари». Новый запуск не перезаписывает паспорта, задания, результаты подбора, ручные оценки или расчёты метрик исходной сессии.

## Обновление в WSL с сохранением данных

1. Распакуйте полный архив в новый каталог `/home/ganie/StockExpert3.9.3`.
2. Дождитесь завершения текущих заданий или отмените их через интерфейс.
3. Выполните, указав фактический каталог прежней установки:

```bash
cd /home/ganie/StockExpert3.9.3
STOCKEXPERT_PROJECT=stockexpert-backend bash update_preserve_data.sh /home/ganie/StockExpert3.9.1
```

Если рабочая версия находится в `/home/ganie/StockExpert3.9.0` или `StockExpert3.9.2`, замените только последний путь. Скрипт копирует именно её `.env`, сохраняет прежнее имя Compose-проекта и подключает существующие тома. Новые пароли не создаются. `init_env.py` и `docker compose down -v` для этого обновления не запускайте.

Скрипт проверяет наличие прежнего тома PostgreSQL и таблиц, останавливает приём новых заданий, создаёт приватную резервную копию `postgres.dump` и `.env` в соседней папке `stockexpert-backup-ДАТА-ВРЕМЯ`, выполняет миграцию 0007 и сравнивает количество прежних сессий, документов, строк, заданий и результатов подбора до/после миграции. Если обнаружены активные расчёты или другая база, обновление останавливается.

Миграция 0007 только создаёт таблицу `normalization_experiments` и индексы. Старые таблицы не очищаются и не переименовываются. PostgreSQL, MinIO, Qdrant, Ollama и кеш моделей используют прежние тома. Резервная копия из исходного ZIP также оставлена в полном выпуске без изменения.

Откройте `http://localhost:5173`. Если вместо прежних сессий появилась пустая база, не загружайте материалы заново: проверьте имя `STOCKEXPERT_PROJECT` и существующий том. Скрипт рассчитан на исходное имя `stockexpert-backend`; при другой прежней конфигурации укажите её фактическое имя.

## Как посчитать только регулярки

1. Войдите администратором и откройте **Для разработчика**.
2. Выберите уже загруженный экспертный эталон. Если его ещё нет, загрузите JSON/XLSX через существующую форму. Эталон должен соответствовать тому же исходному Excel по SHA-256.
3. В таблице **Сессии с этой базой** отметьте **одну** сессию с подготовленными исходными строками. Повторно загружать и нормализовать базу через LLM не нужно.
4. В блоке **Эксперимент H1: регулярные выражения** нажмите **Рассчитать только регулярки**.
5. Дождитесь статуса **Завершён**. Обработка идёт в отдельном сервисе `worker-regex` на CPU. GPU, Ollama, DeepSeek, векторизация, таксономия и подбор не вызываются.
6. Откройте **Паспорта и ошибки**: видны значения, цитаты, правила и расхождения с эталоном. Скачайте JSON с полным снимком/паспортами/ошибками либо CSV со сводными метриками и временем.

Строка «Сохранённый F1 исходной сессии» берётся из уже существующей оценки того же эталона, без её пересчёта. Если она пуста, используйте прежнюю кнопку **Рассчитать метрики выбранных сессий**: она оценивает сохранённые LLM-паспорта без нового вызова моделей. После этого новый regex-запуск сохранит и эту исходную оценку в своём снимке сравнения.

Каждый намеренный повторный запуск создаёт новую запись истории. Повторная доставка одного HTTP-запроса с тем же ключом не создаёт дубликат. Завершённые результаты не перезаписываются при повторной доставке задания. Исходные строки, их SHA-256, версия эталона, версия/хеш правил и результат сохраняются в PostgreSQL; изменение исходной сессии после старта не меняет снимок эксперимента.

## Какие правила реализованы

- Типовые слова и сокращения определяют контекст: кабель, труба, электродвигатель (`Эд.в.`, `эл.дв.`), арматура, подъёмный кран, шкаф. Это подсказка типа, а не результат проверки H2.
- Кабель: `N×S`, в том числе `3х95+1х25`. Основная и дополнительная группы сохраняются раздельно, жилы с разным сечением не смешиваются.
- Труба: первичная пара наружный диаметр/стенка; наружный диаметр не приравнивается к DN. Дополнительные компоненты составной трубы отмечаются для проверки.
- Явные единицы: напряжение, ток, мощность, частота, обороты, давление, масса. Длина, ширина и толщина извлекаются при явной подписи. Поддержаны десятичная запятая и преобразования кВ→В, мА→А, Вт→кВт, кГц→Гц, бар/кПа→МПа, м→мм.
- DN/Ду, IP, климатическое исполнение, ограниченный словарь кабельных марок/сталей, метрическая резьба, присоединение и явно подписанные марка/производитель.
- `без вилок` сохраняется как отсутствие комплектации. Диапазоны, отрицания и противоречивые значения не превращаются в достоверное скалярное значение.
- Неизвестные марки и недостающие параметры не угадываются. Наименование сохраняется из источника; произвольное раскрытие сокращений в названии не выполняется.

Версия: `regex-mtr-v1.0.0`. Правила находятся в `stockexpert-backend/app/services/regex_normalization.py`. Они не читают экспертные ответы. Изменение правил меняет хеш и требует отдельного нового прогона. Перед итоговым сравнением зафиксируйте правила и отложенную тестовую выборку; не подгоняйте правила по ошибкам закрытого теста.

## Метрики и корректное сравнение

- `P = TP / (TP + FP)`, `R = TP / (TP + FN)`, `micro-F1 = 2TP / (2TP + FP + FN)`.
- Совпадения полей, псевдонимов, единиц и значений считаются теми же функциями, что и для сохранённых LLM-паспортов. Неверное значение даёт FP и FN; неподдержанное дополнительное поле учитывается так же, как у LLM.
- **Полнота строк**: доля строк, где найдены все размеченные параметры. **Точность полных строк**: все размеченные параметры найдены без лишних значений. Их знаменатель — число строк эталона; они не подменяют micro-F1 по значениям. Строки без размеченных значений не считаются полностью восстановленными.
- Неполный экспертный эталон ограничивает интерпретацию: известные, но не размеченные корректные поля могут попасть в FP по принятой общей методике. Экспертную схему и разметку нужно согласовать одинаково для всех методов.
- Время правил включает только извлечение и преобразование строк. Очередь, чтение исходного Excel, запись в базу, проверка эталона, таксономия и поиск в него не входят. p95 — по длительности отдельных строк. Отдельно сохраняются время работника, окружение и пропускная способность.
- Историческое время LLM может быть измерено на другом оборудовании и с другим составом этапов: автоматический коэффициент ускорения не вычисляется.
- **H2/H3 не рассчитываются в этом режиме** и остаются пустыми. Старые результаты LLM по категориям и поиску не выдаются за результаты регулярных выражений.

## Если эксперимент остаётся в очереди

```bash
cd /home/ganie/StockExpert3.9.3/stockexpert-backend
docker compose -p stockexpert-backend ps
docker compose -p stockexpert-backend logs --tail=100 worker-regex beat
docker compose -p stockexpert-backend up -d --no-deps worker-regex beat
```

Очередь хранится в БД, публикация выполняется beat каждые 10 секунд. После потери работающего CPU-обработчика запуск помечается ошибкой при отсутствии heartbeat более 10 минут; новый запуск создаётся отдельной записью. Частичный результат не объявляется завершённым экспериментом.

## Проверка выпуска

Проверены извлечение/единицы/сложные строки, отсутствие вызовов LLM, неизменность исходных паспортов и истории, повторная доставка, изоляция организаций, отказ при активной обработке и миграция заполненной базы 0006→0007. В тесте миграции сравниваются все строки прежних таблиц. Проверены TypeScript, production-сборка и действия нового интерфейса. Проверки используют тестовую SQLite-базу; Docker-стек и PostgreSQL на компьютере пользователя в этой среде не запускались.

Фактические метрики ваших складских данных появятся после запуска у вас. Результаты тестовых фикстур не являются доказательством качества на рабочей базе.
