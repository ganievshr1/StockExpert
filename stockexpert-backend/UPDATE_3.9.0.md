## Установка с сохранением всех расчётов

Этот выпуск обновляет существующую базу. Не выполняйте `docker compose down -v`, `docker volume prune`, `reset_stack.py` или повторную генерацию `.env`: это не требуется для экспертных метрик. Архив не содержит личных паролей. Сохраните **свой прежний `.env`**, имя Compose-проекта `stockexpert-backend` и существующие Docker volumes.

1. Завершите или отмените активные задания в приложении. Закройте вкладки других пользователей на время обновления.
2. Скачайте оба новых ZIP в Windows Downloads.
3. Откройте VS Code → терминал WSL Ubuntu. Если ваш проект всё ещё находится в `StockExpert3.8.0`, выполните:

```bash
cd /home/ganie/StockExpert3.8.0
unzip -o /mnt/c/Users/ganie/Downloads/stockexpert-backend-3.9.0-Ganiev-Shamil.zip -d .
unzip -o /mnt/c/Users/ganie/Downloads/stockexpert-frontend-3.9.0-Ganiev-Shamil.zip -d .
cd stockexpert-backend
bash scripts/upgrade_preserve_data.sh
```

Скрипт проверяет отсутствие активных заданий, останавливает backend/worker/beat, делает PostgreSQL backup и копию `.env` в соседнюю приватную папку, собирает сервисы, отдельно запускает миграцию и возвращает сервисы в работу. **MinIO, Qdrant, Redis и Ollama должны оставаться запущенными**, как в прежней установке. Если они были остановлены, после миграции выполните `docker compose -p stockexpert-backend up -d --no-deps redis minio qdrant ollama`, затем `docker compose -p stockexpert-backend up -d --no-deps backend worker beat`. Повторная загрузка весов моделей не нужна: используется прежний `ollama_data`.

После успешной миграции обновите фронт:

```bash
cd /home/ganie/StockExpert3.8.0/stockexpert-frontend
docker compose -p stockexpert-frontend up -d --build
```

Обновите страницу `http://localhost:5173` через Ctrl+F5. Логин и пароль приложения остаются прежними. Пароль `ADMIN_PASSWORD` не меняет уже существующего пользователя автоматически.

## Что делает миграция

Цепочка `0001 → … → 0005 → 0006` добавляет только таблицы `expert_datasets` и `expert_evaluations`, индексы и внешние ключи. Таблицы сессий, документов, паспортов, результатов подбора, ручных оценок, времён и пользователей не очищаются. Повторное `upgrade head` безопасно.

Соединение Alembic теперь закрывается корректно; PostgreSQL выполняет миграцию в транзакции с advisory lock, предотвращающим одновременное обновление схемы. Пароль PostgreSQL передаётся отдельным параметром через SQLAlchemy `URL.create`, поэтому символы `@`, `/`, `#`, `:` и `%` не повреждают адрес подключения.

Ошибка `password authentication failed` означает несоответствие пароля роли в **существующем томе**, а не ошибку схемы. Верните исходный `POSTGRES_PASSWORD` из прежнего `.env`/резервной копии. Миграция намеренно не сбрасывает учётные данные и не удаляет тома. Если исходный пароль утрачен, сначала сохраните backup и отдельно восстановите доступ администратора PostgreSQL. Не используйте `alembic stamp head` для сокрытия ошибки: это не создаёт отсутствующие таблицы.

Если миграция завершилась ошибкой, скрипт остановится и оставит backup. Не продолжайте запуск приложения до устранения причины. Диагностика:

```bash
docker compose -p stockexpert-backend logs --no-color --tail=100 postgres
docker compose -p stockexpert-backend run --rm --no-deps migrate
```

## Вход в раздел

Под учётной записью с ролью `admin`: **Для разработчика** в основной навигации. Раздел виден сразу, без раскрытия настроек. На сервере все его API требуют административную роль и ограничены организацией пользователя.

Загрузите **один** файл: `StockExpert_expert_reference_Ganiev_Shamil.json` или соответствующий XLSX. Повторная загрузка идентичного файла не создаёт копию. Изменённый эталон становится отдельной записью с контрольной суммой и своей историей оценок.

Выберите сессии с той же базой и нажмите «Рассчитать метрики выбранных сессий». Совпадение определяется по SHA-256 исходного Excel, листу, физической строке и исходным ячейкам, а не по имени файла, UUID паспорта или названию модели. Копии доступных остатков могут содержать меньше строк: покрытие и пропуски показываются явно.

Готовые сессии оцениваются сразу; выбранные активные сессии — автоматически после завершения задания. Сохраняются названия моделей из паспортов, настройки и ID заданий, показатели качества, время, детали ошибок. Модели не вызываются. Ручные оценки не заменяются эталоном и не перезаписываются. Внутри «Проверки качества» доступны все паспорта, тип позиции, поиск, 10/25/50/100 строк на странице, предыдущее/следующее изделие, полный JSON и все поля схемы.

## Протокол метрик

- H1: micro Precision/Recall/F1 по техническим значениям. Корректный `null` не даёт TP; неверное значение даёт FP и FN. Неизвестные ключи модели учитываются как FP. Сопоставление ключей использует явный словарь псевдонимов в эталоне. Неточная схема названий может снизить балл: расшифровка показывает ключи для пересмотра единого словаря. Наименование оценивается отдельной Accuracy.
- H2: оптимальное взаимно-однозначное сопоставление кластеров с экспертными классами, венгерский алгоритм. Метрики L1, конечных категорий и L3 различаются. Третий уровень нельзя заменить концом двухуровневого дерева. Если L3 нет, показатель недоступен. В этой программе по-прежнему используется LLM-таксономия; HDBSCAN не добавлен.
- H3: Recall после первичного поиска, Recall@1/5/10/150, Precision shortlist, MRR, nDCG@10. Все релевантные пары из эталона входят в знаменатель Recall, в том числе отсутствующие в найденных кандидатах. Для H3 должен совпадать TXT. Эталон содержит все пары базы. Неопределённые пары исключены с явным учётом покрытия; при них MRR/nDCG не выдаются как полные оценки.
- Время этапов включает все сохранённые попытки сессии. Для новых запусков записывается время отдельных запросов подбора (поиск + правила + reranker + сохранение, без индексации). Из этих замеров вычисляются p50/p95. У старых запусков таких замеров нет. Один запрос не даёт устойчивой оценки p95.
- В текущем поиске остаются Dense + BM25 + RRF; SPLADE не добавлен. Нет измерений полным Cross-Encoder по 12 000 строкам, регулярного/HDBSCAN baseline или бизнес-времени специалиста: эти сравнения нельзя восстановить из старых логов.

98 строк и один запрос — проверочный набор. Recall@150 на нём не доказывает качество отбора 150 из 12 000. Для предоставленного TXT в эталоне релевантны строки 8, 9, 32 по критерию точной марки и 3х35. Возможность замены другой маркой, длина и эксплуатационное состояние не подтверждены.

Ранее сохранённые результаты **сессий** доступны без повторной обработки. Если старый код уже перезаписал паспорта внутри одной сессии, удалил её или потерял Docker volume, эта версия не восстанавливает утраченную историю. Сравнение использует текущие сохранённые паспорта и последний совместимый завершённый подбор. Более новый незавершённый/повторный расчёт явно блокирует смешивание с прежним подбором.
