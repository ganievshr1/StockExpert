## Быстрый запуск через Docker

Нужны Docker Engine с Docker Compose и Python 3 для генерации настроек. Команды выполняются из каталога бэкенда; на Windows удобно использовать WSL2.

```bash
python3 scripts/init_env.py
```

Скрипт создаёт `.env` со случайными ключами и паролем администратора и не перезаписывает существующий файл. Откройте файл локально, сохраните `ADMIN_USERNAME` / `ADMIN_PASSWORD` и выберите модель:

- Локальный вариант выбран по умолчанию: `LLM_DEFAULT_PROFILE=qwen3-8b`. Профиль использует `qwen3:8b-q4_K_M` без рассуждений. Размер модели и скорость зависят от оборудования; GPU в данном compose не настроен.
- DeepSeek: задайте `DEEPSEEK_API_KEY` и `LLM_DEFAULT_PROFILE=deepseek`; проверьте доступное для вашей учётной записи имя в `DEEPSEEK_MODEL`. Профиль и поддержка DeepSeek сохранены из исходного проекта. В этом режиме текст передаётся внешнему API.

Затем:

```bash
docker compose up -d --build
docker compose exec ollama ollama pull bge-m3
docker compose exec ollama ollama pull qwen3:8b-q4_K_M
```

Генератор Qwen нужен при выборе соответствующего локального профиля. `bge-m3` используется поиском независимо от выбора генератора. Для других локальных профилей команда загрузки показывается в интерфейсе. Reranker по умолчанию включён; его веса загружаются при первом применении в `model_cache`. Для запуска без него задайте `RERANKER_ENABLED=false`; это изменит ранжирование.

API: http://localhost:8000/docs. Проверка процесса: http://localhost:8000/health/live. `/health/ready` требует токен и проверяет инфраструктурные сервисы, но не заменяет пробный запуск обработки. Теперь запустите фронтенд по его README. Вход в приложение — по данным администратора из `.env`.

Сервисы: PostgreSQL, Redis, MinIO, Qdrant, Ollama, миграции, API, Celery worker и beat. Compose создаёт сеть `stockexpert-network` для парного фронтенда. Порты API и MinIO Console привязаны к localhost.

## Обновление существующей установки

Сохраните `.env` и постоянные Docker volumes. Используйте прежнее имя compose-проекта (`-p <прежнее_имя>`) или прежний рабочий каталог: изменение имени проекта создаст другие именованные volumes. Сделайте резервную копию существующих данных перед обновлением. Не выполняйте `docker compose down -v`.

Обновите исходники и выполните:

```bash
docker compose up -d --build
```

Сервис `migrate` запускает существующие Alembic-миграции и идемпотентное создание первого пользователя. Версия 3.7 не добавляет изменения таблиц. Исторические схемы, результаты, экспертиза и аудит остаются совместимыми. Новые API используются парным фронтендом; старые API сохранены. Приложение имеет версию 3.8.1, базовый `api_contract_version` остаётся 3.6, расширение UI — 3.7.

## Обработка двух файлов

1. Создать сессию и загрузить остатки `.xlsx` и потребность `.txt`.
2. `POST /pipeline/{sid}/prepare` — определить соответствие столбцов.
3. Проверить схему и `POST /pipeline/{sid}/approve-mapping`.
4. `POST /pipeline/{sid}/start-normalization` — извлечь паспорта всех позиций и построить классификатор.
5. Проверить признаки, правила сравнения и категории; `POST /taxonomy/{sid}/approve`.
6. `POST /pipeline/{sid}/run` или `/matching/{sid}/run` — подбор.
7. Сохранить экспертную разметку `/quality/{sid}/passport/{id}` и `/candidate/{id}`, затем `/quality/{sid}/finalize`.
8. Получить `/metrics/{sid}` и отчёты.

Это не синхронный HTTP-вызов модели: задания исполняются worker, диспетчер и восстановление — через beat. Прогресс приходит по SSE; повторное выполнение не должно дублировать пары.

Лимиты исходного проекта сохранены: файл до 20 MiB, до 25 000 непустых строк Excel, до 256 столбцов, до 16 000 символов в строке, текст потребности до 12 000 символов на документ; до 50 позиций в результате разбиения одного опросного листа. Превышение — явная ошибка. Система не выполняет OCR сканов. TXT принимает UTF-8, UTF-8 BOM, UTF-16 BOM и Windows-1251.

## Что добавлено

- Рабочий стол: поиск, фильтр статуса/периода, пагинация, агрегаты последнего завершённого подбора.
- Безопасная замена входного файла до обработки: новый файл сначала проверяется, затем записи заменяются одной транзакцией. Ошибка чтения оставляет исходный файл.
- Поиск аудита по тексту, типу события, автору и датам UTC.
- Явные добавления категорий и признаков экспертом до утверждения; произвольное изменение структуры через JSON по-прежнему ограничено. Добавление не выдумывает значения в существующих паспортах и не выполняет скрытую переклассификацию.
- Очередь качества: поиск, непроверенные записи и все пары одной потребности, включая пары вне shortlist.
- Настраиваемый PDF/XLSX: сводка, кандидаты/решения, доказательства/источники, аудит. PDF-предпросмотр и скачивание используют один генератор. Текстовые значения XLSX не исполняются как формулы.
- Номера строк и листов в выдаче кандидатов.

Сохранены роли и разделение организаций, неизменяемая конфигурация модели в заданиях, готовые базы, общий статус использованных запасов, экспертные решения, отмена/повтор/очистка, старые экспорты, измерение времени стадий и проверяемая цепочка аудита. Списание остаётся на уровне всей позиции; физическое резервирование, частичное количество, финансовая экономия и интеграция с СЭД не реализованы исходным проектом и не подменены демонстрационными результатами.

## Экспертная проверка и метрики

| Метрика | Эталонные данные |
| --- | --- |
| F1 micro | Явно проверенные значения паспортов. Совпадение непустого значения — TP; неверное значение — FP и FN; лишнее — FP; пропущенное — FN. `2TP / (2TP + FP + FN)` |
| Accuracy | Доля правильных категорий среди паспортов с проверенной и определённой эталонной категорией |
| Precision shortlist | Доля подходящих пар среди оценённых пар shortlist |
| Recall@150 | Доля подходящих пар с рангом 1–150 среди всех подходящих пар **полностью проверенных потребностей данного запуска** |

Вызов `finalize` обязателен. Правка/удаление оценки снимает завершение. При отсутствии эталонов или ненулевого знаменателя возвращается `null`. Значения не вычисляются из закупочных рекомендаций. Разметка относится к одному завершённому заданию и не переносится автоматически на новый подбор. Снимок предсказания сохраняется отдельно; эталон не перезаписывает ответ модели.

Подробная инструкция для эксперта есть также в README фронтенда. Спецификация добавленных маршрутов — `API_3.7.md`, полный контракт — `openapi.json`.

## Структура и разработка

`app/api` — HTTP, авторизация и валидация; `app/services` — прикладная логика (нормализация, таксономия, сопоставление, качество, отчёты, workspace); `app/db.py` — модели и подключение; `app/tasks.py` — выполнение фоновых заданий; `migrations` — схема БД. Новые read-модели рабочего стола и генератор отчёта отделены от HTTP-адаптеров. Исходные интеграционные границы и контракты сохранены.

Для тестов Python 3.11/3.12:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

Тесты сами создают временную SQLite БД и подменяют внешние сервисы на границах. Для запуска API вне Docker нужны PostgreSQL, Redis, MinIO, Qdrant и Ollama с соответствующими URL в `.env`, миграции, worker и beat. PDF-экспорт ожидает DejaVu Sans: Docker устанавливает `fonts-dejavu-core`.

Фактические проверки и ограничения — `VALIDATION.md`. Секреты и тестовые учётные записи в поставку не включены.

## Удаление сессий (обновление 2 октября 2026)

В списке закупочных сессий добавлены «Удалить» в каждой строке и «Удалить все сессии» над таблицей. Открытую сессию также можно удалить через «Управление данными». Одиночное удаление требует подтверждения, массовое — ввода слова `УДАЛИТЬ`.

«Удалить все сессии» действует на все сессии текущей организации на момент запроса, независимо от поиска, статуса, периода и текущей страницы. Сессии, созданные параллельно после начала запроса, в этот список не входят. Права соответствуют редактированию: `admin`, `dmto_expert`, `buyer`. Доступ к другой организации закрыт.

Удаляются запись сессии, исходники Excel/TXT, сохранённые отчёты, векторный индекс, паспорта, результаты, задания, метрики и аудит. Общие запасы, на которые ссылаются оставшиеся сессии, сохраняются. Записи об уже использованных позициях остаются в складском учёте со статусом `USED`: удаление сессии не возвращает их в доступный остаток. Файлы, ранее скачанные на компьютер, не удаляются.

При активных заданиях (`QUEUED`, `RUNNING`, `CANCEL_REQUESTED`) сервер возвращает 409: остановите обработку и дождитесь её завершения. Если внешний сервис недоступен, сессия остаётся в `CLEANUP_FAILED`, новые изменения блокируются, удаление можно повторить. Массовое удаление не является общей транзакцией: успешные удаления сохраняются, оставшиеся сессии и причины ошибок показаны в окне подтверждения.

После удаления обновляются список и счётчики, при необходимости выбирается предыдущая страница. Если удалена открытая сессия, её выбор сбрасывается и открывается рабочий стол. Схема БД не меняется.

## Исправление нормализации и полный сброс (3.8.0)

Ошибочный ответ LLM теперь получает до трёх попыток исправления. Неисправленная позиция сохраняет исходный текст и подтвержденные свойства, попадает в «Требует проверки» и не прерывает обработку других строк. Диагностика содержит файл, лист, строку, спорное имя и историю попыток. Подробности, API и инструкция сброса — [UPDATE_3.8.0.md](UPDATE_3.8.0.md).

Полный сброс пользователей/базы/загрузок/индексов и генерация новых паролей: `python3 scripts/reset_stack.py --yes`. Команда уничтожает данные StockExpert; скачанные модели сохраняются. Фронтенд должен находиться рядом в `stockexpert-frontend`. Для обычного обновления кода сброс не требуется.

## Исправление H2 (3.8.1)

Пропущенный или повторный ID в ответе классификации больше не прерывает весь пакет: корректные ответы сохраняются сразу, проблемные позиции повторно запрашиваются по одной, затем переходят в «Требует проверки». Число попыток — `TAXONOMY_MAX_ATTEMPTS=3`. Исходные паспорта и координаты строк сохраняются. Подробности и обновление **без очистки базы и смены паролей** — [UPDATE_3.8.1.md](UPDATE_3.8.1.md).
