# Обновление 3.8.0 — восстановление нормализации

Совместимо с существующим фронтендом 3.7.0 и его адаптивной версткой. Форматы входа прежние: Excel базы и TXT опросного листа. Изменений таблиц БД не требуется. Удаление одной/всех сессий и прежние API сохранены.

## Ошибки отдельной позиции

`NORMALIZATION_MAX_ATTEMPTS=3` — общее число запросов извлечения для одной позиции, включая первый. При ошибке имени, JSON/схемы, цитаты или характеристики модель получает исходный текст, предыдущий ответ (если доступен) и причину отклонения. Число попыток ограничено диапазоном 1–5; сетевые повторы провайдера настраиваются отдельно.

Если ответ так и не исправлен:

- позиция сохраняется, остальные строки продолжают обрабатываться;
- имя копируется из исходного текста (до 500 символов), если модель не предоставила подтвержденное имя; полный исходник остаётся в `source_text` и цитате;
- из наиболее полезной отдельной попытки сохраняются только проверенные свойства; ответы разных попыток не смешиваются;
- неподтвержденные характеристики остаются пустыми, исходный ответ доступен в provenance;
- паспорт получает `normalization.status=partial` или `source`, `requires_review=true` и историю ошибок;
- в новой таксономии создаётся группа «Требует проверки», без нового LLM-запроса для проблемных строк; при повторном использовании утвержденной базы такие новые потребности остаются без категории;
- при подборе позиция требует экспертной проверки; неодинаковые категории сами по себе не исключают такую пару. Подтвержденное противоречие по проверенным параметрам по-прежнему учитывается.

Проверка имени сохранена: цитата должна буквально присутствовать в исходнике, а имя — в цитате после нормализации Unicode и пробелов. Марки, регистр, кириллические/латинские символы автоматически не подменяются.

Пустые выбранные ячейки Excel не обрывают задачу: сохраняется вся исходная строка с замечанием к сопоставлению столбцов. Если модель не смогла достоверно разделить TXT, весь опросный лист сохраняется одной позицией с обязательной проверкой; догадок о границах позиций нет.

Сохранённые паспорта, включая fallback, повторный запуск не извлекает заново. Исправление исходника/сопоставления требует новой сессии либо предусмотренного приложением сброса данных сессии.

Ошибки доступа к модели, отсутствие модели, недоступность сервисов, проблемы БД и ошибки программирования не маскируются под успешное извлечение. Для временных сбоев действует прежний механизм повторов задания. Изменения касаются восстановления H1 и разделения опросного листа; валидация построения обычных категорий H2 сохраняется.

## Где смотреть проблемы

Существующий фронтенд показывает группу «Требует проверки», исходный текст и коды замечаний в позициях категории. Подробная диагностика доступна в API — фронтенд в этом архиве не менялся:

`GET /api/v1/pipeline/{sid}/normalization-review?limit=50&offset=0`

Нужна авторизация и доступ к организации сессии. Ответ: `total`, `items`. Для каждой позиции:

- `passport.source_location`: `document_id`, `document` (имя файла), `sheet`, `row`;
- `row_kind=excel_row` означает номер строки Excel, `requirement_position` — номер выделенной потребности; `source_line` содержит строку исходного TXT, когда её можно определить;
- `passport.normalization.errors`: номер попытки, причина, спорное имя и цитата;
- `issues`: код, сообщение, документ, лист и строка;
- `passport.normalized_attributes`: сохранённые характеристики.

Те же дополнительные поля есть в обычных API паспортов. В параметрах задания есть `normalization_review_count`. Маршрут также доступен через Swagger: http://localhost:8000/docs.

## Полный сброс в WSL

**Следующая команда уничтожает пользователей, сессии, файлы, результаты, экспертные оценки, аудит и индексы StockExpert.** Файл `.env` заменяется: генерируются новые SECRET_KEY, пароли PostgreSQL, MinIO и администратора, а также ключ доступа MinIO. Старые логины пользователей и токены перестают работать. Имя нового администратора — `markov_f`, его пароль случайный. DeepSeek API key очищается; новый профиль по умолчанию — локальный Qwen3-8B.

Распакуйте архив в `/home/ganie/StockExpert3.8.0`, заменив файлы бэкэнда. Каталог фронтенда должен оставаться рядом:

```text
/home/ganie/StockExpert3.8.0/stockexpert-backend
/home/ganie/StockExpert3.8.0/stockexpert-frontend
```

Затем из Ubuntu WSL:

```bash
cd /home/ganie/StockExpert3.8.0/stockexpert-backend
python3 scripts/reset_stack.py --yes
```

Скрипт сначала проверяет Compose и собирает оба приложения. До успешной сборки данные не удаляются. Затем останавливает проекты `stockexpert-frontend` и `stockexpert-backend`, удаляет только тома `postgres_data`, `redis_data`, `minio_data`, `qdrant_data` с метками этого проекта, заменяет настройки и поднимает сервисы. Миграции и seed создают пустую базу и нового администратора. Shell-переменные старых паролей не подменяют новые настройки в ходе сброса.

Тома `ollama_data`, `model_cache` и Docker-образы сохраняются. Недостающие `bge-m3:latest` и `qwen3:8b-q4_K_M` скачиваются автоматически. Глобальных `prune` и удаления чужих томов нет. При ошибке после замены `.env` новые пароли уже находятся в этом файле. Не повторяйте `--yes` для обычного перезапуска: он снова удалит данные.

```bash
nano .env
docker compose -p stockexpert-backend ps -a
docker compose -p stockexpert-backend logs --no-color --tail=80 migrate
```

Для входа используйте `ADMIN_USERNAME` и `ADMIN_PASSWORD` из нового `.env`, не `POSTGRES_PASSWORD`. Файл имеет права 0600; пароли не выводятся скриптом и не входят в архив. Интерфейс: http://localhost:5173. Сервис `migrate` с завершением `Exited (0)` — нормальный результат.

Старые образы могут содержать старый код, но не используются после пересборки. Скрипт не отзывает внешний API-ключ в кабинете DeepSeek и не удаляет резервные копии `.env`, созданные вручную вне проекта.

Официальная документация команд: https://docs.docker.com/reference/cli/docker/compose/up/ и https://docs.docker.com/reference/cli/docker/volume/ls/.
